# 博世 Ray 混合计算实践

> DataFun Agentic AI Summit「AI Native数据湖让企业Agent拥有统一的智能数据底座（腾讯云专场）」客户演讲（博世 BOSCH × 腾讯云）。主题：**统一算力底座：Ray 混合计算实践——建设统一平台，支撑在线推理、离线训练与大数据计算**。配套英文演讲见 [[bosch-lance-ray-data-production]]（同一大会的英文场次，聚焦 Lance + Ray 的数据生产方法论）。

## 业务背景：自动驾驶 AI 数据闭环平台

博世建设自动驾驶 AI 数据闭环平台，覆盖从数据采集到模型部署的全流程闭环（8 个环节）：

1. **数据采集**——自动驾驶车辆产生海量驾驶数据
2. **数据存储**——多源数据统一存储，安全可靠
3. **数据处理**——分布式计算框架支撑大规模数据处理
4. **特征生成**——特征提取与向量化，生成高质量数据表示
5. **自动标注**——AI 自动化标注，提升标注效率与质量
6. **模型训练**——大规模模型训练
7. **模型部署**——模型部署上线，服务实际场景
8. **闭环反馈**——效果监控与数据回流，驱动持续优化

承载底座为云原生数据平台（弹性扩展、高可用、安全合规、高性能），并强调全链路可视化（数据流转全程透明可控）、数据驱动决策、安全与合规、高效敏捷更新。

## 背景与挑战：从分散算力到统一底座

原状痛点（三类）：**资源分散**（多集群、多地域独立运行；缺乏统一调度，资源利用率普遍偏低；运维成本高，扩缩容效率低）；**算力浪费**（业务波动明显，跨集群资源无法互补；高峰期资源紧张、低谷期大量 GPU 空转；资源浪费严重，成本居高不下）；**体验割裂**（多套平台并存，入口分散；使用方式不统一，学习成本高；用户体验割裂，协作效率低）。

现状示例：按组分配、按业务线分配、多人共用一台机器（当前资源分配现状）。

方案：**建设统一算力平台，基于腾讯 TKE 部署 Ray 集群**。

## 统一资源调度方案

**TKE 统一资源池 + 云 API/KubeRay 双通道，博世 ARENA 平台集成管控**：

- **博世 ARENA 统一管控台**：统一入口——创建/销毁/扩缩容/监控所有 K8s 工作负载
- **云 API 管控通道**：腾讯 Ray 集群全生命周期管理；控制台可视化 + 监控告警
- **K8s API 通道**：KubeRay Operator 灵活控制；非 Ray 负载原生 K8s 管理
- **TKE 统一资源池**：CPU 节点池 | NVIDIA GPU 节点池 | 海光 DCU 节点池；自动扩缩容、资源配额、节点亲和性调度

三个关键收益：**开发即产线**（全局资源池、自动调度）、**统一算力平台**（容器化开发）、**排队与抢占**（作业编排）。

## 三类部署需求，一个统一底座

Ray on TKE 统一支撑三类负载，统一入口、统一调度、统一扩缩容：

| 负载 | 场景 | 特点 |
|------|------|------|
| **推理服务** | 自动标注、tagging、embedding | 快速响应、持续在线 |
| **数据处理** | 去畸变、抽帧、清洗、挖掘 | 批量 CPU 任务、高吞吐 |
| **模型训练** | 大规模训练 | 稳定大算力、长时间运行 |

### 推理服务：数据闭环中的关键一环

Ray 集群部署、异构资源调度、模型 actor 常驻。智驾数据闭环：视频/传感器数据 → 预处理 → **Ray Serve 推理**（自动标注、tagging 标签、embedding）→ 按任务调度异构资源：

- 模型大、CUDA 生态依赖强 → **NVIDIA GPU 集群**
- 国产化适配需求 → **海光 DCU 集群**（Tagging 等）

关键机制：**模型 actor 加载一次、常驻共享内存、推理响应更快**。

Ray 推理服务的两个核心优势：

1. **天然流水线并行**（以自动标注为例）：CPU 预处理（去畸变、尺寸调整、格式转换）→ GPU 模型推理（检测模型运行）→ 输出自动标注框——处理完一批即送入推理，无需等待全部完成
2. **单卡多实例 + 弹性启停**（以 tagging/embedding 为例）：恢复 Actor 实例、快速恢复、GPU 按需释放——提升 GPU 利用率，灵活响应业务峰谷，降低推理成本

### 数据处理：Ray Data 统一编排海量预处理

处理链路：海量原始数据（视频 + 传感器数据，每天海量产生）→ 镜头去畸变 → 视频抽帧 → 异常帧清洗 → 有价值场景挖掘 → 训练可用数据（全部为 CPU 密集型、高并发）。

Ray Data 编排价值：数据从 COS 自动读取 → 分布式分片处理 → 自动写回存储；自动拆分任务、统一管理并发、平台负责调度与容错。

**分片容错**（海量数据处理稳定高吞吐）：传统痛点——任务量大失败代价高，中间失败一次几十小时进度可能全部白费；Ray Data 解法——分片独立处理：分片独立、失败局部重试（只重试该分片）、完成分片不受影响、批量写回 COS。业务同学无需担心中间失败，整条链路稳定高吞吐。

### 模型训练：从训练到推理的产线闭环

- **异构 GPU 集群统一调度**：两类训练集群自动按需调度（平台按模型适配情况自动调度）——NVIDIA GPU 集群（生态成熟，适合主流模型训练）+ 海光 DCU 集群（国产化适配，满足自主可控需求），由 Ray 调度器统一调度
- **开发即产线，训练到推理无缝衔接**：训练环境（环境、镜像、依赖）→ 模型训练（Ray Train 分布式训练）→ Ray 推理集群（Ray Serve 直接上线，无需重新调试环境，环境完全一致）
- **排队与抢占**：低谷期更快拿卡；高峰期保障关键任务优先调度

## 闭环：从申请资源到业务闭环

统一算力底座流程：申请开发环境 → 发起训练任务 → 推理部署 → 业务交付（用户不关心资源）。
