# 狍子AI 的知识工程与记忆工程

**演讲**：王思懿，狍子AI（2026 Agent 大会「Agent记忆工程论坛」，DataFun AGENTIC AI 超级智能体系统架构峰会，22 页）

标题副题：有记忆 · 有知识 · 会进化的 AI 伙伴。核心理念页引用："算法和数据同等重要"（— Feifei Li）、"Context is All Agent Need"、"持续沉淀，动态可发展的知识体系"。

目录：01 结构化数仓的知识工程；02 非结构化文档的知识工程；03 记忆工程；04 未来展望。

## 企业知识底座：三类知识来源

| 来源 | 内容 |
|------|------|
| 01 结构化数仓 STRUCTURED DW | 元数据、SQL 资产池、数据看板、血缘数据…… |
| 02 非结构化文件 UNSTRUCTURED DOCS | 业务知识文件、周报、日报、外部事件 |
| 03 人脑中的隐性知识 TACIT KNOWLEDGE | 对话中再次产生的记忆 |

## 01 结构化数仓的知识工程

### 从数据到图谱（四步流水线）

**STEP 01 数据源接入**：接入丰富的结构化知识（引擎元数据 / 血缘 / SQL 资产等），并叠加紧密相关的文档作为业务支撑，形成"数据 + 文档"双源的抽取原料。

**STEP 02 确定性解码 + LLM 抽取**：规则/查表先把算子、#变量#、字段、SQL 表"翻译成人话"（零 LLM）；剩下"是什么业务概念"交给 LLM——但抽取的节点类型与关系类型必须落在预定义的有界本体 Schema（**8 类节点 · 15 种关系**）内，越界即拒绝。示例：`el_vid_type_id –is #pinlei1#` → 规则解码 → 字段「一级视频类目」= 品类(动漫) → LLM 抽取受 Schema 约束。节点类型举例：业务指标 / 分析步骤；关系类型举例：分析步骤 -作用于- 某指标上。

**STEP 03 对抗性质量审查**：LLM 抽象是质量风险最高的环节，在抽象与建图之间插入独立的对抗性审查：生成者（Extractor）与审查者（Adversary）分离，审查者主动挑错（类型误判 / 该并未并 / 关系逻辑 / 粒度 / 漏抽），打回修正，有界迭代；另有确定性 Validator（证据真实性 / 类型准入 / 关系白名单 / 覆盖率 / 呈现层泄漏，零 LLM）；Arbiter 裁决。

**STEP 04 跨源归一 + Grounding + 建图**：归一化是防爆炸的关键，Grounding 是可信取数的保证，两者都确定性执行。示例：看板 / SQL / 文档三源「播放UV」→ 合并为 MERGED NODE（Metric · 播放UV，多源溯源）→ GROUNDING 回接取数坐标（图卡证据 / 文章段落 / 库表字段）→ 准入图谱。

**图卡样例**（业务落地示例）：「有效消费 UV」指标图卡——"内容当日有效消费去重人数，是周报 Top 列表 ORDER BY 字段"，别名：有效消费人数、消费UV、有效口径；取数参数：imp_date（分区日期，格式 YYYYMMDD）、top_n（返回 Top N 条，默认 100）；输出 table；执行实现 SQL；图关系含 DERIVED_FROM、ORDERS_BY、MEASURED_BY、READS_FROM 等（图中另有内容点击率 CTR 节点）。

### 图检索与问答（三步）

**STEP 01 从一句话到相关子图**——三个动作把自然语言问题「翻译」成图上可消费的知识：
1. NER 认名词：从一句话里挑出业务名词（播放UV · 品类 · 归因）
2. Grounding 落到节点：名词 → 图上真实概念（播放UV → Metric 节点、品类 → Dimension 节点、归因 → AnalysisMethod 节点）
3. PPR 找邻居：从种子扩散，把"真正相关"的东西冒出来（相关工作流：播放波动归因链；相关图卡：品类播放趋势 / 端分布；相关段落：归因方法论文档）

**STEP 02 组装结构化上下文**：把检索出的概念、推荐图卡、工作流链、文档段落、看板筛选变量等组装成 Agent 可直接消费的结构化上下文，含 field_key / cardId / bizId 等取数坐标。构成：CONCEPTS（Metric / Dimension + field_key）、CARDS（bizId + pageId + cardId 可直接取数）、WORKFLOW（Workflow → Step 有序归因链）、PASSAGES（段落证据 · 背景/方法/口径）、FILTERS（筛选变量字典 + 默认值）。

**STEP 03 Agent + MCP 取数**：Agent 沿工作流链逐步 MCP 取数、读数，"取不到真实数据就不编数字"。流程：REASON（沿 Step 链决定下一步取哪张卡）→ MCP CALL（query_card / sql_query）→ OBSERVE（读数 · 校验筛选生效）→ ANSWER（标注筛选/cardId，可信作答）。

### 图谱治理

- **图谱更新**：三种更新模式统一入口——REPLACE 覆盖（重建目标图）、ADD 增量（并入新 source）、REMOVE 下线（移出 source）。任何更新都先明确本次目标 source 集，再进同一条确定性流水线。
- **治理 · 受控演化**：越界类型待人审，不擅自扩张 schema；冲突进治理台，软冲突不静默覆盖。TYPE PROPOSALS（越界概念候选 · 人审确认）；CONFLICTS（同概念不同字段 · 软冲突入库）；REVIEW（治理台展示 · 人工裁决）。

### 知识底座的 Loop Engineering

生产、消费、治理互相牵引，让知识持续沉淀、被使用、被校准：
- **生产**：从对话、文件、数仓和工作流里不断沉淀知识
- **消费**：在任务上下文中检索知识，让回答和决策更贴近现场
- **治理**：识别过期、低质量和重复知识，避免越积累越混乱

数仓特异化：面向数仓元数据的逆向抽取——用有界 Schema 把散落的字段、SQL、图卡沉淀为业务概念骨架，让抽出来的每个节点从一开始就受控；以业务概念与分析工作流为检索单元，让 Agent 顺着数仓天然的指标—维度—口径脉络取数，而非模糊召回；冲突概念引入人审，不让 LLM 引入更多随机性。

## 02 非结构化文档的知识工程

### 原始文件-多类型文件预处理

- **PDF**：自动提取文本内容，保留文档结构和格式，支持表格识别与元数据提取
- **Excel / CSV**：解析表格数据，自动识别表头与数据类型，支持多 Sheet 处理
- **HTML / JSON**：结构化数据解析，支持嵌套对象抽取与字段映射转换
- **PPT**：提取幻灯片文本与备注，保留页面层级关系和演示逻辑
- **图片**：OCR 提取图中文字，支持场景识别与视觉内容描述生成
- **视频**：语音转文字提取字幕内容，支持关键帧抽取与视频主题分析

### 非结构化文档知识化：三种结构 · 三种检索

同一份非结构化文档入库时被**同时**保留成三种结构：原始段落、稠密向量、知识图谱。三种结构回答的问题不同——字面命中 vs 语义近似 vs 关系遍历，任何一种都无法替代另外两种，所以检索天然分三种，由 Agent 按问题形态择路。

| 检索 | 存储与查询 | 典型场景 |
|------|-----------|---------|
| ① Grep 检索（字面/正则，原文段落） | 原文保留不做变换，交给 Agent 用工具按字面/正则直接扫，一字不差 | "这个字符串在哪份文档里"——编号、型号、条款号、错误码，一个字符都不能错；向量检索会把 HT-2024-0912 和 HT-2024-0921 视为"高度相似"，Grep 逐字符区分、不被相邻编号污染 |
| ② 向量检索（Embedding，向量空间） | 切分后 chunk 被 embed 成向量入库，查询同样向量化，按语义相近度召回，问法可以完全脱离原文 | "问法和文档字面不一样"——用户说人话、文档用行话，同一意图跨表述、跨语种、跨风格："客户抱怨到账慢"匹配"资金结算延迟处理"，关键词一个字都不重 |
| ③ 图检索（Nodes + Edges，知识图谱） | 入库时 LLM 抽取实体与关系，落成实体页 + 关系边；查询先定位入口实体，再沿边遍历拿到关联全景 | "答案在实体之间的关系上，而不在任何单段文字里"——归属、依赖、演化、影响面；从"条款"页出发沿 applies_to 一遍遍历，就一览无余 |

### 生命周期治理（Vitality Index）

- **STAGE 1 评分**：量化每个节点的健康度，形成可比分数。知识库：chunk 级 Vitality Index——脉动 25% · 呼吸 20% · 循环 20% · 代谢 20% · 免疫 15%；知识图谱：图谱级 Vitality Index——过时页 · 别名冲突 · 弱关系 · 摘要缺失 · 孤立边 · 孤立页。
- **STAGE 2 检索加权**：高活力节点优先召回，冗余内容下沉。知识库检索结果按活力分重排，高质量内容优先返回，检索质量随使用而增强；图遍历跳过已归档/低分实体页与弱关系，遍历路径始终紧凑，图谱结构持续自愈。
- **STAGE 3 清理**：诊断结果自动落成治理动作。知识库对长期未引用内容递减分值，清理过期片段，输出结构化诊断报告；图谱低活力实体自动归档，冲突实体合并，保持图谱整洁。

## 03 记忆工程

### 记忆机制：三类记忆各司其职

| 类型 | 存什么 | 来源 | 作用域 |
|------|--------|------|--------|
| **PERSONAL 个人记忆** | 性格/沟通风格、编码/语言偏好、AI 行为规则、兴趣/价值观（跨项目通用，刻画"这个人是谁、怎么合作"） | 主动洞察 · 用户确认后落库；用户主动管理 | SCOPE：用户级 · 跨所有项目通用 |
| **PROJECT 项目记忆** | 项目事实、技术决策、架构约定、团队规范（空间内团队共享，沉淀"这个项目怎么做"） | 主动洞察 · 用户确认后落库；用户主动管理 | SCOPE：空间级 · 项目成员共享 |
| **DAILY LOG 每日日志** | 按 session 归档：讨论了什么、做了什么决策、得到什么结论（近期讨论过的话题、敲定的口径与结论、因为什么做了某些决策） | LLM 简短摘要，按天保留；系统自动归档 · 会话结束触发 | SCOPE：用户级 · 按天分片 · 事件流 |

### 记忆的三种使用方式

同一批记忆分三路消费：直接注入 prompt、向量检索、图检索，各自擅长不同问法。

- **① CONTEXT 直接入上下文**：不走检索，每轮对话按预算裁剪后拼进 system prompt。来源：个人记忆 · 项目记忆 · 最近 1 天日志。典型场景：Agent 遵守用户的硬性偏好与行为规则；接着最近一天的话题往下聊，不用重述背景；沿用团队已敲定的口径/术语/架构约定。
- **② VECTOR 向量检索 · 语义相似**：分块 embed 成稠密向量，问法与记忆字面不一致时靠语义命中。来源：个人记忆 · 项目记忆 · 每日日志；加工：按 ## section 切块，逐块 embed 向量入库。典型场景：换说法/口语 vs 术语仍能命中——问"周报格式是啥来着"→ 命中日志"周报采用 概览 + 指标异动 + 结论 三段式"。
- **③ GRAPH 图检索 · 关系遍历**：节点按预先规定的类型分层，顺着有向边遍历，答案在关系里而不在正文里。加工：节点按预定义类型分层，不是自由聚类——identity / goal / decision / preference / fact / event；边按预定义关系类型建立——updates / result_of / contradicts / caused_by / part_of / related_to。典型场景：沿着日志与决策之间的连线追溯因果/演化——问"周报格式为啥改成三段式"→ 顺 updates 边找到原两段式漏掉指标异动的反馈日志。

**三路融合**：三类记忆按预算直接注入 prompt；向量 + 图两路 RRF 混合检索。

### 记忆的生命周期治理（五个阶段）

为什么要治理：记忆只进不出，几个月就变成"过期偏好、重复条目、临时上下文"的仓库——召回越来越钝，预算越用越紧。让每条记忆都有一条"像人一样"的生命线，五个阶段围绕同一个健康分闭环，让记忆规模自收敛。

| 阶段 | 机制 | 类比 |
|------|------|------|
| STAGE 01 写下来 Encode · 建立记忆 | 值得留下的事实与偏好被写入图谱，并给一个初始重要度——越关系到"你是谁"，分数越高 | 像人第一次听到一件事，越关乎身份记得越牢 |
| STAGE 02 用一次就更牢 Reinforce · 强化 | 每次被召回命中，"最近使用时间"就被刷新——用得越多，越难被淡忘 | 像常走的路会被踩出来，常被问起的事实自己会浮上来 |
| STAGE 03 慢慢淡忘 Decay · 时间衰减 | 后台每天重算一次健康度——时间把分数往下拉，访问把分数往上抬，全自动、无需人工 | 像人的记忆不用就会淡，想不起来说明已经不重要 |
| STAGE 04 相似的合成一条 Consolidate · 归纳 | 说法不同意思一样的记忆被识别为孪生对，分高者胜出、弱者并入，并留下溯源边 | 像人把多次听到的同一件事，归纳成一条更笃定的印象 |
| STAGE 05 真正没用的遗忘 Prune · 软删除 | 健康度过低即打上"已遗忘"标记——不物理删，只是不再召回；身份类记忆永不自动清 | 像被遗忘但没真消失的往事，关键时刻还能被唤回 |

**记忆实例**：目标 90%——"用户对写作相关技能感兴趣，正在了解可用的写作技能选项"（6/8/2026）；偏好 60%——"Dashboard should use a deep dark color theme style"（5/28/2026）；待办 70%——"新加入的成员需要先熟悉现有流程，并制定个人 OKR 目标"（6/16/2026）；决策 80%——"决定使用曝光三要素、拍摄步骤、构图技巧作为摄影入门教学的核心内容"（5/21/2026）。示例对话："根据我的记录，你目前已经写过了 data-analytics、data-cleaning 等 5 篇文章。Statistical Analysis A/B Testing 尚未写过，可以作为新方向。"

## 04 产品示例

狍子AI 核心能力知识卡片演示（会话文件）：制作知识卡片展示狍子核心能力（知识库、长记忆、多类型 AI 产物），使用 OmegaDash 引擎生成视觉化卡片（赛博朋克风格）。六大核心能力：将文档、数据、资讯汇聚到一处，自动整理、智能问答、生成洞察——"看到别人看不到的机会"；会记住你的偏好、做过什么，越用越懂你，下次不用重复背景；支持文档、文件夹、书签、对话记录、笔记等多类型文件，自动理解、索引、语义搜索，把散落信息变成随时可调用的活知识；web 演示稿、文档报告、图片、表格、代码，所见即所得；自定义或安装技能；一句话生成数据洞察——直连灯塔、数据库、MCP 工具，业务数据触手可及。核心公式：**业务知识 × 业务数据 × 市场情报 = 个人参谋部**。
