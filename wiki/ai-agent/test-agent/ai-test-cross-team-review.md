# AI 测试自动化跨部门交流会综述

网易内部跨部门研讨会实录（林琳整理，2026-08-28 发布）。**音乐、效工、严选、雷火、有道**分享实践，**智企、元气、传媒、智邮**参与讨论。各团队路径差异：

- 云音乐：深耕 SDD 流程中的**分层测试自动化**体系（→ [[test-agent-harness-paradigm]]、[[mara-test-platform]]）
- 效率工程部：平台化、系统化的质量工程建设（→ [[etest-quality-platform]]）
- 严选：单服务**接口自动化**的工程化落地（→ [[yanxuan-api-test-agent]]）
- 雷火：游戏运营活动的**全链路数据测试**（→ [[config-driven-data-testing]]、[[cc-qa-skill-suite]]）
- 有道：小团队**人机协作**的跨端质量实践（→ [[youdao-codex-testing]]）

## 一、各团队关键数据

| 团队 | 核心数据（原文口径） |
|------|---------------------|
| 云音乐 | 客户端 L1-L2：7 个需求约 500 多个用例（试点团队）；L3 用例较少，自动化通过率约 20% 出头；L4 定点推进，每端稳定 500 个回归用例、每月成本约 4000 元；服务端人不介入首轮通过率约 55%，人与 AI 沟通后基本可到 90%+（服务端比较纯粹、能力成熟度高）；客户端只算 e2e 用例准确率约 20%，服务端接近 100%；视觉回归单端 500 用例每天运行成功率 90% 多 |
| 效率工程部 | 整体测试效率提升约 40%；新场景 Web 端 UI 自动化覆盖率约 80%；外包规模从 70+ 人优化至 40 人（8 月组织调整又合并入 10 人至 50 人） |
| 严选 | 已在 30+ 个需求落地；数据在本服务 DB、入参结构简单、单接口调用场景一次性成功率约 50%；开发本地 agent 约 50% 需求可无干预自主完成 |
| 雷火 | 无间端游年报 85 个配表分支、138 个数据库字段全量覆盖；全流程人工 ≈33.2 小时 → skill 自动化 30~60 分钟，**测试时间提效 33~66 倍** |
| 有道 | 1 名测试 + 3 个 Codex Pro 账号：17 天（11 个工作日）三端推内测、42 个安装包；基础兼容回归口径约 210 人时；项目消耗约 63.31 亿去重 Token；3750 个翻译组合约 6 小时全覆盖 |

## 二、焦点议题

### 1. 提效指标的口径

- 效率工程部重点看「**开发比测试的比例**」与「**测试等待时长**」（提测后到测试接入的时间差）
- 智企考核**需求吞吐率**（需做粒度归一化），同时看基于 CR 复杂度的测试工作周期下降；把用例自动化规模、L1-L4 各层自动化比例、代码覆盖率等过程指标拆到三级部门考核；准确率/召回率考核横向团队
- 补充共识：**提测后到上线交付的整体周期也要看**；等待短不代表提效，执行特别长同样有害

### 2. 端到端提效的难点

- 智企云信（IM UIKit，16 套代码/49 个仓库）：逻辑测试一个平台能覆盖其他端问题，但 UI 交互问题每端各不相同；UI 自动化用例每端覆盖 60%-66% 的情况下，单版本多平台仍出现 200-300 个 bug，质量提升始终在走下游。**API 自动化已完全左移几乎无瓶颈**（出接口说明即生成、提测前直接跑），UI 侧则是痛点
- 云音乐：多端差异可前置——以某一端为基准其他端对照，或同时跑多个模拟器本地对比产出报告（类似投票：多数一致的端正常、不一致的端有问题）；上游 PRD 语义识别、页面跳转逻辑、组件库补全后，UI 自动化准确率与效率会有较大提升

### 3. 测新场景的 AI 落地

- 云音乐：最终愿景是测试作为监督者只做用例与产物监督、不再手工执行，但目前**测新覆盖仅约 25%**——部分用例生成调试成本不经济；开发对测试生码常有「第一次就 100% 跑通」的不切实际期待，需要组织绩效指引与目标拆解，本质是「CTO 工程」，头部技术 1 号位不关心、仅靠横向约束很难推进
- 测新要找 ROI 正向的项目范围：小项目收益有限，一定规模体量的项目适合「自动化工具 + 整体测试架构设计」结合；中间的确定性环节（异常场景、表现是否符合预期、性能验证）可优先确定性交付
- 终极理想：把测试提炼的用例当「真理」，与它对不上一定是研发错

## 三、四条共识

1. **AI 负责理解与生成，确定性交给工程，人负责风险判断**——多个团队不约而同达成的协作范式
2. **数据和业务知识是真正的壁垒**——生码能力趋同后，造数能力、知识库质量、环境适配成为决定性因素
3. **分层比全覆盖重要**——不追求全自动 e2e，让不同层次的测试由最合适的角色负责
4. **从「人做事」到「人定规则、AI 做事、人审结果」**——这一范式迁移正在加速

会后期望推动的实质合作方向：度量口径对齐、harness 工程共建、测试资产跨团队复用。
