# 有道 Codex 跨端质量实践

有道（刘哲分享）以桌面端 AI 语音输入产品「**网易叭哥说**」为例的跨端质量实践——人机协作分工：**人定义任务给判断依据，Codex 补充复述验证执行，人做决策**。

## 背景：极小团队的极限交付

1 名客户端研发 + 不到 1 人服务端 + 1 名测试（一半精力 + 1 实习生）。从拿到第一个版本到三端推内测仅 **17 天（11 个工作日）**，期间收到 42 个安装包（Mac M/Intel/Universal + Windows x64）。按基础兼容回归口径仅此一项就需约 210 人时——于是用 **3 个 Codex Pro 账号 + Computer Use** 换时间和人力。

## 四步协作法

1. **人先测一遍示范定规则**：约 30 条用例，经 skill 扩充至 240 条
2. **Codex 持续扩充验证并留证**：区分产品问题 / 条件不足 / 脚本失败
3. **新包回归老问题**：当前电脑上 n 个版本持续自动化测试
4. **多机批量复制**：统一下发规则与安装包，实现 m 台设备 × n 个版本

## 把可判断的交给 AI

30 种输入语言 × 125 种输出语言 = **3750 个翻译组合**，人工遍历不现实，Codex 约 6 小时全覆盖。

## 四类可复用质量资产

1. **语音自动化闭环**：文本生成音频 → 虚拟声卡定向回环 → 客户端收音 → ASR/润色/翻译，每步可监控
2. **跨端兼容档案**：系统版本/构建号/设备信息统一采集
3. **多语言质量基线**：监控模型与 prompt 迭代影响
4. **可审计报告工厂**：HTML/CSV/JSON 证据一一对应

## 收益与痛点

- 收益：规则越定越准后，Codex 报的 bug 基本都是真问题、很少漏报；项目期间消耗约 **63.31 亿去重 Token**，换来基础回归需 210 人时的跨端验证规模
- 痛点①：视觉方案执行慢——人半小时、AI 约两小时；读图对 token 消耗影响大（能读到界面内容就不读图、读不到才读图）
- 痛点②：单账号额度扛不住高频发包（一天要盯两三个安装包），需多账号并行；每账号每月消耗约 200 美金

## 讨论要点

- **session 管理**：每个项目有独立 session 做一件具体的事；Codex 已支持跨 session 对话，遇到问题可「圈」报 bug 的那个 session 让它去报。**每版本独立 session 避免上下文过长**——测试用例、报 bug 流程、软件版本下载安装分别放不同 session，单线上下文完整流程基本不失真。每次测试生成报告由人审，前几次要说明为什么（行就确认，不行要讲清规则），让它逐渐学会你要什么——把不同职责拆到不同 session，共同汇成一个流程
- **native 支持**：可以，它是视觉方案；但要考虑慢（人半小时它可能两小时）
- **token 成本**：三个号是因为需要测试十余台不同环境设备，一个号扛不住；项目跑 11-12 个工作日消耗约 60 多亿去重 token
