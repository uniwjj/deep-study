# Mara 测试平台与文本用例即脚本

Mara 是云音乐的一站式 AI 自动化测试开发平台，以 WebUI（`raven qa-webui`）为入口承接 [[test-agent-harness-paradigm]] 中客户端 QA 流程与服务端串行流程的落地。

## 一、客户端流程：五阶段 QA WebUI

启动：在 SDD 开发的工程目录执行 `raven qa-webui`，选目标平台（iOS/Android）、填客户端主工程绝对路径，一键启动 Pipeline。五阶段：**用例设计 → 测试方案设计 → 测试代码开发 → 测试执行 → 确认提交**。

1. **用例设计**：基于 PRD 生成文本用例（示例需求 15 条：优先级 P0:7/P1:8；类型边界 6/状态 5/正向 4）。人机分工提示：「检查 AI 生成的用例（删除或编辑），补充遗漏的测试场景」。支持**分模块 review**、用例摘要环形图、精简模式（按比例精简/还原）。每条用例展开后有执行步骤与断言（如 `uiVisible | $.page.guestGuideTip | true`）。
2. **测试方案设计**：生成自动化设计方案文档（说明/不确定项摘要/Section 0 页面-源码对应关系⚠优先 review/入口链路/子页面元素定位表/数据注入方式/前置条件构造策略）。审阅纪律：「重点检查高亮推测项和待确认项（错了阻断生码），以及页面映射和导航路径（错了整批用例作废）。其余章节可快速过」。确认通过后恢复生码。
3. **测试代码开发**：E2E 代码生成完成 → 双确认（测试代码已审阅 + 业务代码已完成）→「确认并进入测试执行」。对应 SDD 流程中测试资产与业务代码在 G_dev_done 汇合。
4. **测试执行**：展示执行结果概览（通过率/通过/失败/总计/耗时）与用例列表。每条用例可挂 **MOCK 接口**（Path + Body 字段，关键字段标注「影响测试用例断言」，其他字段可关注），并自动**扩展异常数据用例**（如 `data.minePrivacyList=[]`）。失败用例可查看测试报告、执行流程、转手工。有未通过用例时无法提交验收；全部通过后「提交 Overmind 测试计划」。
5. **确认提交**：测试周期验收归档，用例同步至 Overmind（示例：10 条、394 条）。

## 二、服务端流程：三阶段串行模式

启动：需求开发完成后 `raven qa-webui --mode server`。三阶段：**用例设计 → 用例执行 → 确认提交**。

1. AI 探索本地变更代码，生成用例和自动化脚本；开发审核测试范围和脚本用例。用例围绕**数据流转和状态**设计（示例 TC-001：接口 `PlaylistAntispamHandleService.selfSeenByPlaylistId(long)`，结构化描述含接口/前置条件/操作步骤/验证条件 `(totalDuration & 16384) != 0`）。为保证调用真实发生且不对后续链路产生副作用，补充**事中 checkpoint 和事后状态清除**。
2. 用例脚本结构化：依赖测试变量（如 `TEST_PLAYLIST_ID`）→ 前置条件（Bean `setup_ensure_normal`）→ 数据快照（执行前/后 SQL 捕获 status_snap/td_snap）→ 执行步骤（Bean invoke_self_seen → SQL query_db_verify → Assert verify）→ 清理步骤（`cleanup_recover`，YAML 声明 target/method/appName/params）→ 调用链检查点（class/method/app/cond，报告显示「应命中 ✅」）。
3. 测试执行：部署到测试环境（pretest），远端执行，本地查看结果；执行失败可通过 CLI 指定 AI 分析和自愈。单用例报告可视化断言结果（示例：断言 3/3——`success=true`；Status 从 NORMAL 变为 SHOW_404（`'0'→'15'`）；totalDuration bit14 被设置（`'0'→'16384'`）），步骤耗时逐条列出。验收后 394 条用例同步 Overmind。

## 三、L4：文本用例即脚本（QA 验证自动化）

QA 核心验证能力：一份文本用例转换成配置型脚本，选设备运行后**每一步都有截图，截图背后是断言结果**（动作记录，绿色代表通过）。

示例：`登录svip用户，打开歌单7122186448（断言：进入歌单详情页，播放按钮可见）→ 点击播放全部（断言：歌曲开始播放，底部播放栏出现，显示当前播放歌曲名）→ 点击底部播放栏右侧的播放列表按钮（断言：@与前一张图对比断言：播放列表前3首歌曲与上一张图的歌单列表顺序一致）`

特点（原文口径）：

- **视觉方案，一份配置多端通用**：iOS、Android、鸿蒙、H5、手表等；支持任意 app
- 低门槛：业务/外包等任何角色可直接用，支持 CLI；只依赖需求，测新场景下提测前基于需求和交互生成自动化用例
- 数据：单端 500 个回归用例稳定运行，通过率 95%；识别准确率 99.84%（609/610）；智能步骤时间 4-5s
- 成本：近 1 个月 62034 个任务实例运行、新增 2466 个任务，AI 成本虚拟价格 4k 元

### 智能步骤三档

| 档位 | 说明 | 定位 |
|------|------|------|
| 单步骤智能执行 | 单步骤推理，准确率较高 | 主流，用于回归 |
| 部分步骤智能体 | 与云音乐特有的造数、登录能力结合，时间可控 | 特性产品混合应用 |
| 整体任务智能体 | 不确定性高、时间长（实验下来有局限，类似豆包手机） | 高阶探索 |

中间方案（确定性+智能混合）：前两步做确定性（登录、造数）、第三步用模糊文字描述智能执行、第四步回到确定性。

步骤类型：打开 app（冷启动）/等待/登录/打开页面（`orpheus://` scheme）/智能点击/ocr 点击（格式：文本#数字 或 文本,偏移X,偏移Y）/智能体·智能执行（自然语言多步指令，如「搜索 mylove，播放第一首歌，点击评论，并发布评论内容 good」）。

## 四、AI 断言与进阶应用

**AI 断言**：输入断言描述 → 「用户意图解析」（检测意图 + 判定标准）→ AI 断言结果 → 检测结论总览 → 异常汇总与建议 → 逐项检测详情（JSON）。可「再次视觉检测」「回写到用例」。

**多图对比断言**：`@与前一张图对比断言：播放列表前3首歌曲与上一张图的歌单列表顺序一致`——平台返回思考过程 JSON（rounds 数组：attempt/ts/image_url/input_description/ai_coordinates/ai_description/outcome=clicked，resolved_coordinate）与对比详情（检测项/结果/说明），对比结果「通过」。

进阶场景：

- **抓包任务/异常测试（高频）**：查看一个/多个动作背后的请求出入参；勾选接口做**故障注入**看异常表现（示例：抓包 Job 按设备聚类 23 台，勾选 `/api/middle/user/interest/svip/send/list`，Body `{"scene": 100004}`）
- **步骤级屏幕录制**：性能任务（如「打开歌单的加载时间」）、视频断言分析（步骤间对比；视频断言失败示例：断言「用户的星火值最终增加20」，AI 识别视频最终星火值仅增加 5 点（124→129），给出「建议检查任务完成逻辑或数值结算配置」）
- **多数据源驱动**：音乐查看多个播放器样式、电商查看不同类型商品的商拼详情表现
- **多设备系统任务**：一起听/IM/双人空间等（设备 A 操作、多设备截图；双设备协同「一起听」：D1 发起邀请、D2 接受加入）

## 五、复用成本

| 能力 | 服务端复用 | 客户端复用 | 说明 |
|------|-----------|-----------|------|
| 文本用例产出 | 可行，现在就可复用 | 同 | 集成在 Raven 里，也可单独 Skill 集成；外部邮箱等已在用 |
| L1 + L2 用例 | — | 可行，复用成本低 | 较少与业务及云音乐工程化体系耦合 |
| L3 | 可行，复用成本中 | 可行，复用成本高 | 客户端与曙光埋点、Mock 基础能力耦合，后续探索无曙光模式与插件化；服务端与 raven、部署/中间件/基础组件版本绑定 |
| L4 | 可行，支持任意 app | 试用 | 建议被测 app 支持一键登录；规模化需设备，平台将支持多租户 |

联系：L1~L3 @果然(王维恒)；L4 @余成章。
