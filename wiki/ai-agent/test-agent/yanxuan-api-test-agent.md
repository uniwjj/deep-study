# 严选 AI 接口自动化

严选（满天星(葛琳琳)、伟杰(张伟杰)分享）聚焦单服务、单接口的 AI 接口自动化实践，整套流程融入 SDD 研发流程，通过自研 skill 实现「**用例生成 → 脚本生成 → 测试执行**」完整流水线。

## 应用场景与亮点

1. **三阶段流水线**：分析 PRD/DESIGN/SPEC 生成全量用例脑图（人读）+ P0 用例文件（AI 读）；深度扫描源码提取接口信息，同时为数据策略提供证据；每个 P0 用例输出**声明式 YAML 脚本**；本地自动执行并生成测试报告
2. **数据构造四级策略**：db_query 数据库捞数（处理约 80%+ 字段）→ 固定值 → 数据工厂 → 用户兜底——分层解决「没有正确数据脚本跑不起来」的瓶颈
3. **双卡片打分映射**：为 Case 与接口入口各建结构化卡片多维交叉打分，解决业务语言与技术语言的语义鸿沟，准确率约 80%，剩余人工兜底
4. **自愈能力**：脚本执行失败时 AI 先自我修订再重执；断言字段用「探索」方式——先执行拿准确响应结构，再修正断言路径
5. **核心设计原则**：**只让 AI 做语义分析和判断，其余全交确定性代码**——变更入口追溯 AI 只裁决约 5% 歧义；gate 文件物理门禁硬阻断；auto-fix 静默修复 + terminate 物理阻断两轮兜底（AI 编造 SQL 表名会被比对真实表结构直接终止）

## 效能与痛点

- 收益：已在 30+ 个需求落地；数据在本服务 DB、入参结构简单、单接口调用的场景**一次性成功率约 50%**
- 痛点①：跨服务链路、数据不在本地（数仓来源/纯 RPC 编排）时结构性退化，**用户侧造数负担成为真正瓶颈**
- 痛点②：3 月组织架构调整后大规模测试资产快速腐化且不可逆；当前开发本地 agent 约 50% 需求可无干预自主完成，剩余难在数据依赖上游链路
- 痛点③：skill 更新可能影响他人需求，需以「**回归集**」迭代重跑验证效果（初始设计时约定一批需求，每次 build 迭代重跑；因 AI 每次跑有偏差，迭代中重新判断，现阶段再加熟悉业务域的人为经验判断）

## 讨论要点

- **脚本质量评价**：脚本与用例步骤一一对应、结构上包含前置/执行/断言/后置等步骤、断言和测试用例保持一致，即认为质量达标；暂无专门指标统计接口边界覆盖效果
- **设计文档表格/流程图处理与遗漏检查**：接口类信息偏代码结构化，操作类偏语言+流程图（AI + skill 处理）；遗漏检查靠**交叉验证**——PRD 核心流程做主体用例框架，再用用例逐点与核心场景逐条匹配，两份文档必须完全核对上；匹配不上的分歧抛出来交人判断；后续会对设计文档做约束性审计
