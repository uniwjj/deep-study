# Agent 长短期记忆系统

**来源**：微信公众号「小林coding」

Agent 的记忆系统分为两层：短期记忆管当下任务不翻车，长期记忆管跨任务攒经验。存储方式、粒度设计、使用场景完全不同。

## 为什么需要记忆系统？

没有记忆的 Agent 每次对话都是全新开始——不记得用户偏好、不记得之前达成什么约定、无法在多次任务之间建立连贯性。

## 两层架构

| 维度 | 短期记忆 | 长期记忆 |
|------|---------|---------|
| 本质 | Context window 中的 messages 列表 | 向量数据库（Vector DB）+ Embedding |
| 生命周期 | 任务结束时清空 | 跨任务持久保存 |
| 作用时机 | 任务执行过程中全程使用 | 任务开始前检索，任务结束后写入 |
| 类比 | 工作台 | 档案库 |

## 短期记忆

短期记忆就是每次调 LLM 时传入的 messages 列表——LLM 当前的「工作台」，上面摆着：
- 用户的指令
- LLM 的思考过程
- 工具调用的结果
- 每一步的中间状态

实现上就是维护一个列表，每次追加 `{role, content}`。每次调 LLM 传**完整历史**而非仅最新一条。

**核心代价**：messages 随任务进展越来越长，context window 装满后会截断早期内容，Agent 开始「遗忘」。

## 长期记忆

### 核心工具

| 概念 | 说明 |
|------|------|
| **Embedding** | 将文字转为数字向量，语义相近的向量在高维空间中距离近 |
| **向量数据库** | 专用存储向量的数据库，核心能力是相似度检索 |

### 写入流程

```
信息 → Embedding模型 → 向量 + 原文 → 向量数据库
```

### 读取流程

```
查询 → Embedding模型 → 查询向量 → 向量数据库相似度检索 → Top-K 原文
```

「语义相似 = 向量距离近」的特性让你不需要精确关键词匹配，语义相近就能检索出相关记忆。

## 粒度设计

粒度直接影响检索质量：

| 粒度 | 问题 |
|------|------|
| 太细（每句话一条） | 碎片化，检索命中不全 |
| 太粗（整次对话一条） | 噪音多，LLM 难以找到有用信息 |

**推荐粒度**：
- 按「**一次完整交互**」存——用户请求 + Agent 处理结果
- 按「**一个独立知识点/事件**」存——如「用户偏好：Python，简洁风格，英文注释」

## 两层配合流程

```
任务开始前：检索长期记忆 → 注入 system prompt
任务执行中：短期记忆维持全过程状态
任务结束后：将重要结论写入长期记忆
```

**短期记忆**保证当前任务的连贯性，**长期记忆**保证跨任务的积累。两层配合让 Agent 不会在中途失忆，也能越用越了解用户。

## WorkBuddy 五类长期记忆模型

> 来源：[[workbuddy-agent-product-design|WorkBuddy Agent 产品设计]]，2026年7月

WorkBuddy 将长期记忆细化为五类（均属**陈述性记忆**），每类有不同作用范围和注入策略：

| 类型 | 存什么 | 系统作用 | 示例 |
|------|--------|---------|------|
| 稳定事实 | 去情境化的稳定事实、长期偏好、已确认的默认假设 | 长期推理前提 | 用户所在城市、常用工作语言 |
| 用户知识背景 | 专业背景、知识水平和熟悉领域 | 调节解释深度和术语密度 | 用户熟悉 Context Engineering |
| 行为信号 | 从多次真实交互观察到的稳定使用模式 | 交互策略调节信号 | 回答前先查看当前工作空间 |
| 表达偏好 | 对表达方式的稳定偏好 | 控制"怎么说"，不影响事实 | 先给结论、减少空话 |
| 会话延续信息 | 当前会话中有价值的目标、决策、进度 | 帮助延续讨论和任务 | 已完成什么、下一步做什么 |

### 陈述性记忆 vs 程序性记忆

WorkBuddy 明确将**程序性记忆（Procedural Memory）**排除在长期记忆之外：

- **陈述性记忆**记录"用户是谁、了解什么、发生过什么" → 提供推理前提
- **程序性记忆**记录"做事方法" → 会直接影响 Agent 推理路径和执行顺序

程序性记忆注入上下文的四个风险：
1. 局部经验被误升为通用策略
2. 干扰模型推理，不再根据当前证据选路径
3. 隐性改写 Agent 行为，缺少版本、评测、审批和回滚
4. 缺少稳定奖励信号和 Eval 时，难以判断是在改进还是积累偏见

**WorkBuddy 的选择：用户事实和历史状态放进 Memory，经过验证的工作方法保存为 Skill**（可版本化、可评审、可测试、可回滚、按需加载）。

### 记忆作用域分层

同一类记忆可以在不同范围内生效，作用范围越大、写入门槛越高：

| 层级 | 示例 | 解决问题 | 典型失效方式 |
|------|------|---------|-------------|
| 当前轮临时上下文 | 刚选中的代码 | 理解当前一步 | 任务结束即失效 |
| 会话/Thread 记忆 | 做到哪一步 | 多轮对话连续 | Thread 结束后归档 |
| 项目/Workspace 记忆 | 架构约定、活跃计划 | 在场景里接着做 | 项目变更或决策替换 |
| 用户级记忆 | 长期表达偏好、职业背景 | 减少反复自我介绍 | 用户修改、撤销或降权 |
| 团队/组织记忆 | 团队流程、术语、边界 | 多人与多 Agent 协作 | 权限变更、制度更新 |

记忆注入分四阶段：冷启动 → 请求理解（按 query 激活候选 memory cards） → 执行中回查原始会话 → 任务收尾时提取候选记忆（去重、冲突检查、作用域判定）。

一个成熟的 Memory 系统需要同时支持：写入、来源查看、用户纠正、冲突替换、时间衰减、降权、删除、回滚和临时停用。
