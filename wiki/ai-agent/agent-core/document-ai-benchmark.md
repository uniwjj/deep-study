# 智能文档 Benchmark 落地实践

> 2026 Agent 大会「Agent评测与治理论坛」演讲：**刘青**（阿里巴巴企业智能·算法智能团队），主题《大模型时代智能文档 Benchmark 落地实践——从评测设计到数据合成，构建面向真实企业场景的文档智能评测体系》。

## 核心论点

理解文档是自动化企业流程的第一步。**单一维度测试无法反映真实生产环境表现**——文档智能的三大核心挑战：

| 挑战 | 表现 |
|------|------|
| 来源复杂 | 扫描、拍照、电子 PDF、网页 |
| 版式多样 | 表单、合同、报告，布局各异 |
| 结构差异 | 同类文档字段定义大不相同 |

四大核心任务：**文档解析、文档分类、关键信息抽取、智能问答**。

## 设计思路与原则

- **全域覆盖**：覆盖企业核心业务场景，不遗漏关键领域
- **全任务覆盖**：覆盖解析、分类、抽取、问答全链路任务
- **分层建模**：从简单到困难，多维度多粒度分层评测

落地目标四步走通：沉淀高价值文档 → 统一数据与指标 → 标准化自动化平台 → 权威开源基准。

## 构建方式

### 数据采集三管齐下

1. **企业内部真实业务文档**：从阿里 60+ 个核心业务域采集近百万份真实文档，脱敏后用于评测
2. **公开数据集整合再标注**：从多个公开文档理解数据集筛选样本，按统一规范再标注，保证一致性
3. **生产系统错误样本回收**：系统性收集实际部署系统中的失败用例与边界 Case，最能反映真实能力（20% Hard Cases）

### 错误归因驱动的难例挖掘

错误归因树覆盖五大任务类型，每种任务有典型错误模式：

| 任务 | 典型错误模式 |
|------|-------------|
| Recognition 识别 | 低质量图像、形变字体、密集小字、手写体 |
| Parsing 解析 | 表格嵌套、跨页结构、图文混排、版式异常 |
| Grounding 定位 | 字段-区域错配、长文本定位、跨页证据 |
| Extraction 抽取 | Schema 语义混淆、隐含字段、开放类别、跨语言 |
| QA 问答 | 多跳推理、证据聚合、答案验证、长上下文遗忘 |

难例挖掘四步闭环：收集真实/生产失败案例 → 按任务类型与错误模式归因 → 定向补充 Hard & Corner Case → 回流评测集，形成迭代闭环。**评测-归因-补样**持续迭代，精准覆盖当前模型的能力盲区。

### SAYRE 文档合成框架

场景感知文档合成（Scene-Aware Document Synthesis），两条路径：

- **Path A · 通用生成**：Few Exemplars → Scene Perception (Content + Layout) → Doc-Schema-Anno Triple → Rendered Image
- **Path B · Error-Driven 生成**：Failure Cases → HTML Template 提取版式结构 → Content Rewriting + 重标注 → Hard Training Examples

优势：无手工模板、可扩展、覆盖长尾场景。

实验效果（UniKIE-Bench 平均 F1）：Sayre-2B 超越所有同规模开源模型，4B 逼近商用水平；合成数据量 Scaling 曲线显示随数据量增长性能持续上升、未见饱和。**关键结论：数据质量与覆盖率与模型规模同等重要——弥合端侧模型与云端大模型的差距。**

## 四个 Benchmark 评测矩阵

### CC-OCR V2 —— 企业困难样本综合评测

5 大 OCR 核心任务 Track：Recognition（文本识别）1790、Parsing（文档解析）826、Grounding（文档定位）1468、Extraction（信息抽取）1009、QA（文档问答）2000，合计 **7,093 高难度样本**、74 细分场景、32 语言覆盖。

特色：20% 未公开生产困难样本、48% 新增标注、唯一同时覆盖 5 大任务的综合评测基准。

关键发现：

- **Grounding 是最大短板**：SOTA 仅 65.73，多数模型 <50
- **任务间严重不平衡**：Rec/QA 与 Grd/Ext 差距大
- Top 模型：Qwen3.6-Plus 综合最优，Gemini 3.1 Pro 识别和提取最强，Kimi K2.5 解析和问答最强
- 结论：即便是 SOTA 模型，在真实企业场景中的文档处理能力仍不够理想——Grounding 对可审计、可追溯的高可信应用尤为关键
- 文档类型细粒度分析：Books/Reports 最易（规则布局、清晰文字模式）；Receipts、Handwriting 最难（密集布局/小字体/低质量、书写风格巨变）。**平均分掩盖弱点，细粒度评测揭示部署风险**

### MMM-Bench —— 多模态多层级文档分类

五层层级分类体系：L1 Business Function（业务功能）→ L2 Business Object（业务对象）→ L3 Business Stage（业务阶段）→ L4 Business Form（业务形态）→ L5 Document Class（文档类别）。

数据概览：5,990 真实文档、12 业务域、5 层级深度。与现有分类 Benchmark 对比：RVL-CDIP（平坦、多域 ✗、多模态部分）、DocLayNet（平坦、多域 ✗、多模态 ✓）、WikiSection（2 级、多域 ✗、多模态 ✗）——**首个同时具备深度层级 + 多域覆盖 + 多模态内容的文档分类 Benchmark**。与阿里企业域业务团队共建，反映真实业务组织逻辑。配套层级树自适应拓展算法。

四大核心挑战：

1. **细粒度语义区分困难**：准确率随层级递降，L1 95%+ → L5 60-70%
2. **领域敏感**：结构化域强、非结构化域弱；Legal 最优 → Marketing 最差
3. **模态融合瓶颈**：纯文本 > 文本+图像+布局，全模态融合能力不足
4. **长尾分布拖累整体表现**：样本分布不均衡，头部 92.1% → 尾部 60.2%

### UniKIE-Bench —— 开放域信息抽取

**Schema-Guided 统一评测范式**：传统 KIE 评测是逐字段问答式，每个字段独立推理，无法捕捉字段间结构关系、效率低；Schema-Guided 给定文档图像 x + 抽取 Schema s，一次推理输出完整结构化键值对（y = M(x, s)），支持跨场景统一评测。特性：Structured（结构化）、One-Shot（单次推理）、Cross-Scene（跨场景）。

Two Complementary Tracks：

- **Constrained-Category KIE**：场景预定义 Schema，反映实际应用中的字段抽取需求（4,472 文档、3 领域、11 场景）
- **Open-Category KIE**：每条文档独立 Schema、无场景假设，要求抽取文档中所有显式关键信息（1,661 文档、4 类型、2 语言）

业界首个同时支持约束类别与开放类别 KIE 的统一评测基准（规模扩大 3×）。

实验发现：

- 闭源和开源模型之间仍存在明显差距：Open-Category Track 上最好闭源模型 Gemini-3-Pro 取得 81.65 分，最佳开源模型 Qwen3-VL-8B 为 67.36
- Form 类文档（碎片化布局和灵活的字段边界）是所有模型最头疼的类型；Receipt 类文档（布局规则、键值明确）表现最好
- 跨语言鲁棒性仍是关键挑战：几乎所有模型在英文文档上的表现显著优于中文文档，与视觉语言预训练中英语数据的优势分布密切相关

Faithfulness 与错误分析——三类典型错误模式：

1. **视觉感知失败**：如 2.32 → 4.32 数字混淆，OCR 基础识别不足
2. **布局感知失败**：字段与空间区域错误关联，识对文字但关联错区域
3. **语义理解失败**：面对复杂 Schema 字段语义混淆，字段语义边界模糊

更高的 F1 通常伴随更高的忠实度，但相近忠实度下 F1 差异仍可能显著。**看到 ≠ 理解，感知 → 布局 → 语义三级能力共同决定最终 F1。**

### DocScope —— 长文档可验证推理问答

任务定义：首个要求模型输出完整可验证推理轨迹的长文档问答基准。数据：1,124 questions from 273 documents，平均每文档 51.3 页。

实验分析三大发现：

1. **答案准确率 ≠ 推理可信度**：答案对但过程错，>70% "答对"并未真正理解文档；即便答案正确，完整证据链最高通过率仅 29%
2. **跨页远距离证据聚合困难**：关键证据分散时，跨页聚合对所有模型极具挑战；真正让文档问答变难的是证据的"散布方式"，而不是文档有多长
3. **"为文档专门设计" ≠ "表现更好"**：通用大模型的基础视觉-语言能力仍是当前天花板；开源模型在长文档可验证推理上已具备竞争力，但与闭源模型的差距集中在精确空间定位和事实忠实提取两个阶段

结论：长文档理解需要轨迹级评测，而非仅靠答案正确率。

## 未来规划

四大方向：评测维度扩展（多页文档/表格嵌套/跨文档推理，挑战更复杂企业场景）、数据合成增强（SAYRE 迭代升级，突破手写文档和混合模态文档合成能力）、评测平台化（在线评测平台、一键式模型评测、自动化报告、动态 Leaderboard）、学术生态建设（联合业界共同制定评测标准，推动开源共建）。

长期愿景：让文档智能评测像 ImageNet / GLUE 一样，成为行业公认的能力标尺，驱动模型持续进步。
