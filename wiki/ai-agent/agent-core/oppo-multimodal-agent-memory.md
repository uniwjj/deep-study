# 多模态 Agent 的记忆工程实践（OPPO）

**演讲**：刘鹏，OPPO AI 中心（2026 Agent 大会「Agent记忆工程论坛」，DataFun AGENTIC AI 超级智能体系统架构峰会，30 页）

演讲主题《看见、记住、行动：多模态 Agent 的记忆工程实践——从手机伴随助手到端侧具身智能体》，目录四部分：01 AI 助手的下一个胜负手；02 小布伴随的流式记忆；03 X-OmniClaw 的端侧记忆；04 展望：下一站，Agent OS。

## 01 AI 助手的下一个胜负手

**手机 AI 助手的多元需求**：天气问答、解题、总结刚刷到的攻略、打开 App 订票页面——"今天的手机助手，不只要答得上，还要看得懂、记得住、做得到"。

**手机 AI 助手的演进**（应用形态变化背后是模型、记忆与 Agent 能力的共同演进）：

| 阶段 | 形态 | 核心技术 |
|------|------|---------|
| 语音助手 Voice Assistant | Siri / 小布早期 | ASR + NLU，规则意图槽填充 |
| 屏幕问答 Screen QA | 截图问答 / 圈选搜索 | OCR + 单轮视觉问答，VLM 单图理解 |
| 实景问答 Real-world QA | 举起手机问眼前的世界 | 多模态融合，实时 VLM 推理 |
| 伴随问答 Companion QA | 持续感知手机使用旅程 | 时序视频流理解 |
| 执行型 Agent Agentic Execution | 规划并完成真实任务 | Agent 编排 + GUI 操作，多步规划与验证 |

## 02 小布伴随的流式记忆

**什么是小布伴随**：不是一次性识屏问答（如 AI 实时看屏对话、打开圈选），而是持续在线的手机使用陪伴。

**设计理念**：常规 Agent（多轮思考、多次工具调用、循环试错、适合后台任务）vs 手机伴随 Agent（减少 Agent Loop、首包优先、单次编排、模块轻量、可降级兜底），并追求"快而可控"（路由前置并行执行、轻量模块 + 规则约束、候选链路、兜底）。"小布伴随既要持续长久的陪伴，也要快速稳定的响应。"

**整体框架**（结构图，部分元素 OCR 对应关系不完全确定）：输入侧包括视频帧流实时采样、用户 Query/语音、ASR 文本 + HAR、端侧 APP 信号；处理链含 ASR 时间窗对齐、屏幕类型判断、动态优先级排序、提问起始帧回溯、全多维意图识别、安全前置检测（打码/禁止共享）、异常帧识别、候选链路并发执行、Fallback 回退机制、联网实时搜索、RAG 语义检索增强、多模态推理、流式渐进输出、伴随式语气控制；记忆侧包括流式 Video Caption（主要内容/次要内容分层）、时序索引、个性化记忆（用户偏好积累）、事件记忆（时序事件归档、场景上下文记录、跨会话持久化）。

### 流式记忆（1/6）重建提问瞬间

系统收到 query 时用户已翻页（如看小红书帖子时提问"刚刚那个多少钱？"）。输入 asr_start + 帧缓存；窗口内无精确帧时取最近帧；重建帧（如"小红书帖子 B @ t0"、最近帧 t-1）送入后续链路。异常处理：帧已过期 → 返回异常状态码；打码帧：标识存在、内容被打码、不可直接使用；禁止共享帧：帧内容置空、仅保留标识 → 返回异常状态码/安全处理。最终形成"提问瞬间上下文"（屏幕内容 + query 文本）送入编排中枢。

### 流式记忆（2/6）屏幕语义时间轴

每 T 秒由 Video Caption Model 打标，始终保留最新摘要；时间轴上排列各时刻的屏幕 Caption（示例含状态栏 14:32、收藏 856、Tab: 发现等）；记忆系统执行检索/存取，召回相关记忆（如"搜索附近餐厅 @ 4T、查看店铺详情 @ 5T"）。

### 流式记忆（3/6）记忆分层与应答全覆盖

长时记忆（Long-term Memory）：历史语义摘要、检索召回、长时记忆检索，覆盖用户全部历史时间（Full Temporal Coverage）；短时记忆（Short-term Memory）：Query 起始 / Query 说话期间 / Query 结束 各阶段帧；当前帧（Current Frame）必选（Always Included）；存在"帧存在但不参与本次应答"（Frames exist but excluded）的处理；模型应答（LLM）输入 = 历史摘要 + 当前帧 + Query 文本，应答触发（Response Triggered）。

### 流式记忆（4/6）实验一：Video Caption 去噪实验

Caption 生成时显式区分：重点信息（页面主体、用户关注对象、任务状态）与非重点信息（导航栏、底部按钮、重复控件、无关 UI）。根据场景选择是否使用非重点信息，全场景应答满意度有 **1.7 个点**的提升。

### 流式记忆（5/6）实验二：持续 Memory 总结

时序问答数据集构造五类问题：实时问答（依赖短时视频信息面）、记忆问答（依赖历史局部记忆）、回溯问答（需要对过去的总结回溯信息）、图文无关问答（问题与画面弱相关）、完全无关问答（不依赖屏幕内容）。页内有"Baseline vs +Mem总结 对比"图，具体数值图中未清晰标注。

### 流式记忆（6/6）OASIS 层级记忆检索框架

**OASIS（On-Demand Hierarchical Event Memory for Streaming Video Reasoning，CVPR 2026）**——无需训练、低成本、可插拔的层级记忆检索框架：把不断增长的视频历史 fold 成层级化事件记忆，而不是把所有帧或片段平铺保存。先把短时间内的连续观察聚合为局部事件，再将相关事件进一步压缩成更高层的语义摘要，形成从细粒度片段到粗粒度事件的层级结构。推理时模型先根据问题判断需要哪类证据，再沿着层级记忆从粗到细定位相关时间区域——既保留长视频关键信息，又避免把大量无关历史塞进上下文，把"记住更多"转化为"按需展开正确的记忆"。页内附方法对比表格，列名与数值经 OCR 无法完整辨认（不确定），未收录。

### 记忆如何被消费（1/4）：核心影响要素与设计理念

长短时记忆的选取和插入方式在不同链路和场景条件约束下有较大差异。核心影响要素：短时记忆选帧策略、长时历史记忆策略、Prompt 要素设计。核心设计理念：时序信息有选择的保留、多源上下文按需注入、退出/兜底机制、特殊场景特殊设计。

**System Prompt 设计要素**（分层结构图，层级标签与内容分组经 OCR 部分对应关系不确定）：身份认知（性格基调、品牌归属）；场景指引层（场景变体身份：标准助手模式/特殊场景模式；实体具体化要求：按场景标签动态注入细化规则；上游信息采纳规则：结合来源回答，冲突时忽略）；历史记忆层（用户问题；多帧画面理解：时间顺序排列、串联完整使用场景；多源上下文注入：RAG、历史视频记忆、记忆仓、用户画像、工具结果；采纳原则：注意代词指代、与画面冲突时无视）；输出控制层（字数五档自适应：确认 10-20 字 + 攻略 150-300 字；表达风格：语气基调约束、禁用表达范围限定；模态来源隐藏：屏蔽内部信息结构、统一对外表述口径；隐私安全：敏感信息统一拒绝）；规范约束层（禁止模糊/消极/自我质疑表述；动态限制追加：根据上下文类型按需注入额外约束；内容策略：拓展场景 vs 精简场景；质量标准：信息密度高、数据具体、贴合画面）。

### 记忆如何被消费（2/4）：视频场景

短时记忆与 query 类型强相关，需要判断是否依赖画面，通常需要全量的短时记忆；长时记忆：问题事件通常长上下文关联性强，检索记忆片段和使用全局总结记忆至关重要；Prompt 设计：场景描述和记忆描述需要完备。示例：Q"主角被袭击好像在故事前期就有伏笔？"→ 结合长期细节记忆提供关键信息；Q"主角这段时间一共经历了多少挫折？"→ 需要长期细节记忆和总结记忆的共同引导。

### 记忆如何被消费（3/4）：教育场景

短时记忆：越接近 query 时间的帧越重要，个别问题不需要视频帧；长时记忆：通常是副作用；Prompt 设计：限制越少越好。页内有"模型 Prompt 长度–满意度"与"模型输出长度–满意度"两张曲线图（教育场景）。

### 记忆如何被消费（4/4）：伴随留痕

基于视觉感知、对话交互与闪记增强的留痕系统。记忆留痕的主要元素：视觉感知（屏幕内的重要信息）、对话交互（提炼用户交互上下文）、闪记增强（用户主动要求重点记下的内容）。最终形成可追问、可回溯的记忆，保存在小布记忆里。

### 场景拓展

- **旅游出行场景**：伴随范式 + 垂域子链路，增强垂域问答执行能力。输入层（用户 Query、视频历史记忆、VLM 意图提取）→ 并发工具调用（生活服务类：餐饮/酒店/景点；本地出行类：火车/机票/长途）→ 结果融合 → 结构化整理 → 相关度过滤 → 模型推理 → 生成回复。
- **直播辅助场景**：伴随范式 + 任务前处理，助力直播带货文案生成 + 在线问答。对应论文 **Click-to-Ask: An AI Live Streaming Assistant with Offline Copywriting and Online Interactive**（离线文案生成模块 + 在线弹幕问答模块 + 基于事件的历史记忆模块，示例设备 OPPO Reno 14）。

## 03 X-OmniClaw 的端侧记忆

**X-OmniClaw 整体架构**：集多模态感知、记忆与执行于一体的多模态安卓端 Agent，真实 Android 设备运行。X 强调跨模态融合，将多源感知信号组织为统一的任务输入，驱动真实移动端环境中的跨应用执行；Omni 表示系统整合三类感知来源：屏幕内的 UI 状态、屏幕外的真实世界视觉上下文、语音输入。三大要点：

- **Omni Perception**：屏幕 + 相机 + 语音统一进入
- **Omni Memory**：工作记忆 + 本地长期记忆
- **Omni Action**：观察 → 推理 → 执行 → 验证

（本地引擎标语：X-OmniClaw Local Engine — Your Devices, Your Driver；输入含 Screen、Gallery Images、User Profile，执行方式含 Trajectory Cloned Execution。）

**Omni Memory：全时空个性化记忆**：多模态长期记忆（User Profile：Interests、Location、Gallery Images）+ 工作记忆（Context、App Settings、Task Progress）+ 记忆构建与使用技能/工具（Scheduled Tasks、Memory-maintenance Skill/Tool；Operations：Filtering、Summarization、Semantic Retrieval）。"工作记忆保证任务不断线，长期记忆让 Agent 更懂用户；安全控制决定这些记忆能不能真正落地到个人设备场景。"

**用户路径记忆——轨迹克隆**：X-OmniClaw 的两种执行方式：Agent Loop（完成开放性任务，可能有较高的时延和成本）；轨迹克隆（对用户的轨迹做事件级记忆，快速完成用户需要长期记住的行为；Trajectory Clone → Skill Card → Trajectory Replay）。

**其他 Demo 展示**：相机识物→电商询价；屏幕跟随→多步读屏问答；主题找图→一键成片。

## 04 展望：下一站，Agent OS

**从 Assistant 到 AgentOS**：AI 从助手入口走向系统级任务调度层。范式转变：以 App 为核心交互单元（先知道用哪个 App、理解页面、一步步手动点击完成）→ 以 Agent 为起点调度一组能力（Agent 解析目标与上下文、跨 App 完成任务、结果可信）。演进图标注"长上下文记忆""主动意图推断"等能力。

**AgentOS 正在成为手机系统的新方向**：Google — Android Intelligence System；Microsoft — Project Solara；Apple — Apple Intelligence & Private Cloud Compute。**端侧记忆：Agent OS 的个人智能基础设施**：
- 本地沉淀：手机、耳机、眼镜、汽车和家庭设备，在本地记录最近场景的多模态记忆
- 跨设备协同：每台设备保留局部记忆，在用户授权下实现安全连接，让上下文跟随用户流动
- 持续个性化：将长期偏好、任务状态与执行经验沉淀为画像和技能，驱动主动服务
