# 专家在环评测

> 2026 Agent 大会「Agent评测与治理论坛」演讲：**王冲**（一面千识 技术 VP，负责 Expert Evals 团队与前沿 Benchmark 探索；经历：蚂蚁集团技术专家、掌阅科技前端负责人），主题《超越 Benchmark：从 CodingAgent 到通用 Agent 的专家》。

## 为什么 Benchmark 还不够

公开 Benchmark 榜单分数持续提高，真实使用中信任与采用意愿没有等比例提高。**不是谁对谁错，而是衡量对象不同**——三个差异：

| 差异 | Benchmark | 真实工作 |
|------|-----------|---------|
| **题目不同** | 题目已经定义好：目标明确、条件固定、标准预设，直接开始解题 | 只有一个目标：要理解语境（背景信息/干系人/历史情况）、补齐信息（缺什么/从哪里找/如何验证）、确认约束与成功标准（有哪些约束/成功的标准/如何衡量），再制定计划、分解任务、推进落地——**真实 Agent 还要先把题目搞清楚** |
| **成功标准不同** | 通过 = 满足显式条件（自动化检查：测试、格式、关键字段） | 可用 = 真正解决问题；可信 = 方案合理、风险可控；可采用 = 专业人士愿意接手（专业判断：方案、证据、风险、采用意愿）——**通过只是最低门槛，真正解决问题才值得采用** |
| **工作方式不同** | 一次作答：中间不给反馈、不做纠偏，只看这一轮是否通过 | 持续协作与收敛：第一次独立作答 → 专业反馈 → 听懂反馈 → 修正根因 → 结果可用；关注听不听得懂、能不能改对、要花多少轮（交互轮次、额外提示） |

**Benchmark 看第一次能不能做对；真实工作还要看它能不能在协作中做成。**

## 方案：专家在环的交互式评估

对比 Benchmark（一次性、跑完即止、模型独立跑一次、pass/fail 静态快照），专家在环（Expert in the loop）是**多轮协作、收敛即止**：

1. **专家命题**：源于真实场景、干净环境
2. **首轮观察**：模型独立跑一次，不做干预（≈ Benchmark）
3. **定向纠偏**：分档提示、记录痕迹
4. **依 Rubric 评分**：多维画像，非单一总结

## 真实案例：Coding GSB 评估项目

一次模型在 Coding GSB（对战式）评估项目，评估过程中对模型匿名处理，模型代称 A、B、C、D。

### 评测实践数据

50+ 累计评估期数、7 评分维度、1300+ 参与评估专家数、单题评估平均耗时 4.28h。

### 本期评估构成

最贴近日常场景的 0-1 生成、Feature 迭代、Bug 修复三类合计占比 70%+；90% 的题目涉及多文件改动，近一半需要跨模块甚至跨系统协同。

### 模型多维能力画像

七维（语义理解、指令遵从、工程质量、交付完整性、用户体验、架构边界、任务规划），分值 1–5，图中刻度 3.0–4.5。总体排序 A > B > C > D：

- **共同强项**：架构边界，4.05–4.33，分差 0.28
- **最大分差**：用户体验，3.13–3.88，分差 0.75（模型 A 3.88 vs 模型 D 3.13）

### 两两对战：胜率与画像互相印证

让 B 模型与 A、C、D 模型分别对比并打分（每组 126 场；A 是国外 SOTA 模型、B 是用户模型、C D 是国内竞品模型）：B 对 C、D 胜率均超过六成；与模型 A 接近，仅相差 4 个百分点。

## 评测质量管理

### 专家准入靠证据，后续治理看表现

流程：多源招募 → AI 筛选 → 匹配 → 动态评级 → 项目准入。专家能力证据（专业经历、资质认证、优秀作品、历史表现）驱动准入决策，入项后看近期表现动态调整——入口看能力匹配，入项后看持续表现。

### 一条数据的质检流程

AI 自动校验（四环节，不通过返回）：

| 环节 | 校验内容 |
|------|---------|
| 题目提交 | 难度、Repo、相关性 |
| 轨迹提交 | 一致性、Feedback、复杂度 |
| Rubrics 合成 | 结构、覆盖、约束 |
| 打分提交 | 冲突、规范、理由 |

专家提交与互审：质检专家 A ⇄ 质检专家 B 交叉审核（题目评分、专家优劣标签、机审反馈），发现问题返回对应环节。每一次机检和互审，都让最终交付更可信。

### 同一起点，同一尺度，结果才可信

- 环境锁定起点：Docker 容器、相同初始态、无 Git 历史与参考答案、VS Code 编辑器
- VS Code 实时观测：过程可见、产物可验
- 评分表锁定尺度：统一维度、统一尺度、评分记录、复核

保证公平、准确、可复现、可审计。

## 从 Coding Agent 到通用 Agent

### 系统把主观判断变成有标准、有证据的共识

评测标准化流程：任务输入（甲方要求、任务材料、交付产物）→ Rubric 合成（评分维度、分档锚点、证据清单：看什么、怎么判、需要什么证据）→ 专家独立评审（独立判断、证据引用、盲审）→ 形成多数共识 Majority Vote（2/3 专家结论一致，超过半数意见一致）。低一致性任务自动进入复核：分歧处理 + 专家仲裁（核验评分证据、定位分歧原因、校准 Rubric），形成新共识 → 规则沉淀回系统。

**不是消除主观判断，而是让判断有标准、有证据、能交叉验证。**

### 每一份专家交付都有一份可追溯的质量报告

文件基础校验服务（专家上传文档、表格、PPT、数据文件，统一进入系统校验）：

| 维度 | 检查内容 |
|------|---------|
| 合规性 | 格式规范、必填项、命名规则 |
| 相似度 | 重复内容、模板套用、版本差异（记录相似位置、比对依据） |
| 数据真实性 | 来源追溯、交叉核验、异常值（记录数据来源、异常线索） |

发现异常 → 定位问题与证据 → 返回对应专家修正。沉淀为可复用的基础服务：统一文件解析、规则引擎、证据记录、异常定位。**系统负责可规则化的检查，专家负责真正需要专业判断的部分。**

### 专家池：持续为任务找到真正懂行的人

专家池持续增长（Coding、法律、投融资、自媒体、前沿科学研究等更多专业领域）、严格筛选（专业经历、资质认证、优秀作品、历史表现）、专家画像 × 项目画像精准匹配（专业领域、任务场景、交付要求、评审标准）→ 对口专家。更深的专家池 → 更严格的筛选 → 更精准的匹配。

## Expert Evals As A Service

标准底座保证专业交付，可选模块按需裁剪：

- **标准底座**：专家匹配、任务设计、结构化 Rubric、独立评审、过程质检、证据记录、多维评估
- **可选模块**（按目标组合）：垂直领域专家、自定义维度、Majority Vote、GSB 对战、跨版本追踪、训练信号

三种典型组合：

| 目标 | 组合方式 |
|------|---------|
| **模型选型** | 能力对照 + Majority Vote + 多维画像 → 选出更适合真实任务的模型 |
| **版本迭代** | 新版模型准入门槛 + 跨版本追踪 + 失误归因 → 看清进步发生在哪里 |
| **训练改进** | 结构化评分标准 + 轨迹与证据 + Golden Solution → 转化为训练与奖励信号 |

可裁剪的不是专业标准，而是围绕目标的服务组合。

## 结论

让真正懂任务的人回到评测回路，我们才能知道 Agent 是否真的胜任。
