## 跨端协同：YOYO 智能体

### AgenticOS：调度多设备多 Agent 协同

AgenticOS 是连接物理世界和数字世界的最佳桥梁，支持多端感知、多端连接、多端共享。连接多硬件（AIPC/Pad、AI 眼镜、机器人、AI Phone、无人机、手表/耳机、其他 AI 设备）与多智能体（图库、旅游、文档、居家、搜索、餐饮、办公、出行、游戏、购物、生活、娱乐……）。

- **多端感知**：跨端数据协同
- **多端连接**：任务无缝流转
- **多端共享**：统一服务调度

### 系统架构：YOYO 智能体运行核心（IPTAM）

| 层 | 含义 | 内容 |
|----|------|------|
| I | 感知 | 多模态输入、意图预理解 |
| P | 规划 | 任务拆解、Replan 动态调整 |
| T | 工具 | MCP 标准化、Skill / A2A 标准化 |
| A | 执行 | 跨应用跨设备、GUI 界面操作 |
| M | 记忆 | 记忆汇聚、上下文融合 |

核心闭环：意图理解 → 任务规划 → 工具调度 → 行动执行 → 记忆反馈 → 上下文更新。让 Agent 具备"吃一堑长一智"——每一次行动的结果都变成它的"经验教训"，存进记忆，不再犯同样的错。

端云架构：端侧（执行）= Node 感知、RTC 实时链路、Node 精准执行、隐私数据本地处理；云侧（大脑）= Gateway 中转、Context 整合、Plan 拆解、Tool 调度、Memory 沉淀。隐私安全底座：沙箱隔离 – 权限管控 – 行为追溯 – 端侧加密；未经用户授权，数据不出端；Agent Runtime 全链路行为可追溯。

### 示例 1：多 Agent 协作链路

用户输入"帮我创建一个每天早上 8 点打开 WiFi 的任务"。

- 第一步：用户找主 Agent（main-agent，前台接待）
- 第二步：主 Agent 判断这是任务类需求，转给领域专家（domain-agent，后台专家，session）
- 第三步：领域专家拆解工作分配给子 Agent（a1 负责规划，a2 负责通知）
- 第四步：子 Agent 完成，结果汇总给领域专家
- 第五步：领域专家将结果以"用户视角"回传给主 Agent（main_review_message as user）

链路：用户只跟前台对话 → 前台找专家 → 专家拆活分给干活的人 → 干完活 → 专家整理结果 → 交回前台 → 前台再回复用户。

### 示例 2：用"点菜→做菜→上菜"理解 Agent 运行架构

用户："来一份宫保鸡丁，少辣"

- L1 前台接待（接口层）：服务员接单（WebSocket 异步点单 / Agent-API 同步点单），记录订单内容传给后厨
- L2 调度中心（AgentRuntime）：AgentRouter（"宫保鸡丁 → 川菜档口"，路由到目标 Agent）、WorkerManager（安排工位，排队执行）、AgentRun（选模式：FastMode 快餐模式简单菜快速出 / ThinkingMode 精烹模式复杂菜边做边想 / ProMode 大厨模式满汉全席全套能力）
- L3 厨师准备（AgentHandle）：拿菜谱（提示词模板装载）、拿工具（刀具/锅具 = 工具装载）、拿技能（特殊技法 = 技能装载）、看顾客偏好（上下文处理：少辣、过敏史）
- L4 厨师烹饪（AgentCore · 核心循环）：`while(菜没做好)`：看顾客档案（ContextStore → 上下文/历史口味）→ 回忆上次做的（记忆系统 → 短期/长期记忆）→ 尝味道、决定下一步（ModelRouter → LLM 推理）→ 动手操作（工具层 → 切菜/炒菜/调味）→ 还不够好？→ 继续循环
- L5 特殊档口（技能层）：skill_call——川菜技法（专属 Skill）、分子料理（第三方 Skill）、用户自创菜谱
- L6 上菜通道（端指令框架）：Node → 设备执行——端侧执行（炒菜出锅）、通知顾客（上菜）
- 结果返回 → 接口层 → 用户："您的宫保鸡丁好了，少辣版 ✓"

### 示例 3：Agent 三重决策——谁来干、谁先干、怎么干

Router 决定"谁来干"，WorkerManager 决定"谁先干"，AgentRun 决定"怎么干"——三者构成调度中心的"路由-排队-执行"铁三角。

- AgentRouter（路由调度）→ "这个活该谁干？"："整理会议纪要"→ 路由到 PRO 模式 Agent；"今天天气"→ 路由到 FastMode Agent；"帮我抢茅台"→ 路由到 GUI Agent
- AgentWorkerManager → "安排谁干？怎么排队？"：创建 Worker → 分配工位；全局线程池 → 统一调度；Worker 执行 → 排队干活；销毁 Worker → 回收资源
- AgentRun（多模式执行）：FastMode（简单模式）/ Thinking（思考模式）/ ProMode（Pro 模式）

### 示例 4：跨端执行，让智能体跟着用户走

用户："帮我整理一下昨天会议录音的要点，生成一份文档"

- 手机端（地铁上）：语音 → 指令框架 → 模式路由到 PRO 模式 → exec(录音转文字) → 生成 x 条要点 → 保存到 Personal Workspace
- PC 端（工位上）：PC 上线 → Node 状态变更 → Gateway 感知 → Gateway 刷新设备列表 → PC 读取"会议纪要.md"继续展开 → 发邮件 → 手机收通知
- Personal Workspace（共享文件柜）：数据统一 + 记忆连续 + 能力互补 = 跨端智能体

### 跨设备协同的三个关键技术点

1. **Personal Workspace（共享文件柜）**：手机写入"会议纪要.md"，PC 读取，PC 写入"会议纪要-详细版.md"
2. **Session 管理（上下文记忆）**：手机 session_id=123, agentId=YOYO；PC session_id=123, agentId=YOYO ← 同一会话，"认出是刚才那个任务"
3. **Node 协同（多设备联动）**：PC 执行发邮件（gateway-call → 指令框架）；手机收通知（notify → 灵动胶囊）

无跨设备 vs 有跨设备：单设备下手机整理要点 → 保存到手机，到工位后要重新找文件、重新开始；跨设备下手机整理要点 → 保存到 Personal Workspace，PC 继续展开文档、发邮件，手机收通知"已发送"。

Personal Workspace = "共享文件柜"，Session = "记忆纽带"，Node 协同 = "多设备联动"——三者让智能体从"单设备助手"进化为"跨设备管家"。

## 主动服务：YOYO 任务

**架构**：用户通过自然语言创建 Trigger + Action 组合的自动化任务（Workflow），主 Agent 拆解规划，配一配框架注册围栏监控，条件触发后自动执行。五步合一：听懂 → 拆解 → 封装 → 设警 → 执行（从「听命」走向「自动」）：1 感知（多模态输入、意图预理解）→ 2 规划（任务拆解、Replan 动态调整）→ 3 任务（封装 DSL、标准化任务描述）→ 4 围栏（注册围栏、Trigger-Action）→ 5 端侧执行（定时触发、Node 精准执行、灵动胶囊通知）。

**YOYO 任务的完整生命周期**（10 阶段）：
1. 用户输入：语音/文本 → ASR → Query
2. 端侧上下文准备：组装请求 → 网关 → 云侧
3. 主 Agent 规划：任务拆解 [trigger | action] → 条件拆解 [围栏] → 条件推理
4. 主 Agent 输出判断：拒识处理 [不符] → 追问处理 [槽位] → 完整处理 [封装]
5. 任务下发与围栏注册：trigger → 工具 → 围栏适配 → 结果解析 → 下发框架 → 注册
6. 用户反馈：任务卡创建成功 → 灵动胶囊显示 → 用户可编辑任务 [手动 | 自然语言]
7. 围栏监控与触发：感知围栏状态 → 满足触发条件 → 三重拒识校验 [通过 | 识别]
8. 任务执行：任务执行框架 → 指令框架 → 指令路由 [端工具 | 云工具] → action 执行
9. 重新规划：前置 action 完成 → 主 Agent 重新规划 → 生成后续 action 指令 → 任务执行
10. 结果通知与闭环：执行结果 → YOYO 任务服务 → 结果显示 → 状态通知 → 日志记录

### 示例 1：一句话多任务

用户："早上 8 点打开蓝牙；早上 9 点打开 WiFi；晚上 10 点打开省电模式"——一句话，3 个任务。

- 主 Agent 拆解：任务1 trigger=time(8点) action=bluetooth(打开)；任务2 trigger=time(9点) action=wlan(打开)；任务3 trigger=time(22点) action=power_saving(打开)；三个任务绑在一起，workflowGroup 标识
- YOYO 任务处理：策略"一个订单三个包裹 → 每个包裹单独发货"，每个包裹独立下发转 DSL
- 配一配框架处理：收到包裹 → 每个包裹单独注册围栏（围栏1：8:00 → 蓝牙；围栏2：9:00 → WiFi；围栏3：22:00 → 省电）

### 示例 2：Replan 延时决策

用户："每天 7 点，查询天气，如果下雨，提醒我带伞"——只知道"7 点做啥"，具体做啥，7 点再定。

- 主 Agent 拆解：任务 trigger=time(7点) action=到时候再规划；备忘："查天气，下雨就提醒带伞"
- YOYO 任务处理：时间到了！→ 执行 replan
- 主 Agent 重新规划（Replan）：加载天气 Skill → 查天气 → 获取结果；分支1 下雨 → 出门带伞！→ 执行提醒；分支2 晴天 → 不用管了！→ 任务结束
- 结果通知：下雨 → 灵动胶囊"已提醒您出门带伞"；晴天 → 灵动胶囊"今日天气晴好，无需带伞"

**总结**：普通任务——创建时 trigger + action 都确定，触发时直接执行 action；Replan 任务——创建时 trigger 确定，action = "到时候再想"，触发时先查信息 → 再决定做什么 → 执行。确定性的事提前规划，不确定的事到时候再说。

## 回顾与愿景

整体架构回顾：交互层多模态输入（语音/手势/眼神/文字）→ 用户意图 → YOYO Agent（智能体调度中枢）：多模态感知（视觉–听觉–触觉–上下文）、上下文会话管理（多轮–多模态–跨应用）、长短记忆（短期上下文–长期用户画像）、规划行动（任务拆解-推理-动态调整）、工具调用（Skill / MCP / API）、反馈执行（Action–监控–纠错）。开发安全 – 隐私可控：沙箱隔离 – 权限管控 – 行为边界约束 – 端侧加密。

**AI 新势能——Robot Phone 机器人手机**：AI 跨越屏幕 → 进入物理世界 → 多模态具身交互；2026.08 首发，AgenticOS 内核。终端边界的消融：从"数字大脑"到"具身载体"的范式变革——手机不再是手机，是 AI 的身体。

**Agentic OS 展望：新一代伙伴型多模态智能体操作系统**：① 意图驱动（以意图为中心，非应用为中心）；② 自然交互（以感官为入口：声音|手势|眼神|动作）；③ 主动智能（以 Agent 为内核：主动规划|主动服务|主动执行）；④ 天生跨端（以一脑调度万端：多设备|多 Agent）。荣耀正在定义这场代际革命的技术标准。
