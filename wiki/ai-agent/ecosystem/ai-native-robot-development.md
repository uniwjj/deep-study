# AI-Native 机器人开发新范式（地瓜机器人）

2026 Agent 大会「消费场景Agent实践论坛」演讲《AI-Native 机器人开发新范式——聊天造物，打造机器人开发的"Codex"》，演讲者李乔龙（地瓜机器人）。

## 公司：地瓜机器人

起步于 2015 年诞生的地平线，地瓜机器人是业界领先的机器人软硬件通用底座提供商。承载着「成为机器人时代的 Wintel」的品牌初心，为具身智能的前沿科研探索、消费机器人的应用落地、中小创客及个人开发者创意开发提供全链路的开发基础设施。

- 核心：旭日智能计算芯片 + RDK 机器人开发者套件（RDK：Robotics Developer Kit）
- 已合作：全球 200+ 中小创客、100,000+ 个人开发者，为全球 600 万+ 用户带来智能化体验；在扫地机、割草机等垂直行业市场份额领先
- 覆盖场景：人形机器人、四足机器狗、陪伴机器人、无人机、割草机、扫地机
- 出货数据（过去一年，赋能各品类机器人客户）：600 万+ 芯片出货量、100+ 下游机器人品类、10 万+ 生态圈开发者
- 全链路开发基础设施：机器人一站式开发平台（AI 数据生成、AI 数据标注、模型训练、多模态仿真、Agents/Copilot、可视化开发）+ 机器人应用中心 NodeHub（YOLO-World、3D Occupancy、VSLAM、双目深度检测、VLM/VLN/VLA、Locomotion）+ 机器人操作系统（TogetheROS.Bot、ROS 2、Model Zoo、RDK OS (Optional Real-time Core)）
- 应用中心：https://developer.d-robotics.cc/nodehub

**算力矩阵（以 BPU 为核心，覆盖全算力需求）**：从 5 TOPS 到 600 TOPS 多档（含 10/30/100/300/600 TOPS），面向人形机器人、四足机器人、物流车、AMR、服务机器人、扫地机、割草机、陪伴机器人、消费无人机等品类；规划中档位包括 560 TOPS（int8，预计 2026 年发布，人形机器人、物流车等）、>300 TOPS（int8，预计 2027 年发布）、80/128 TOPS（int8）、>30 TOPS（int8）、10 TOPS（int8）、5 TOPS（int8）。

## 行业背景：AI 从聊天窗口走向自主执行

三年多时间，AI 从聊天窗口走向自主执行。模型能力提升只是表象，真正的变化是交互范式从 Chat 转为 Agent：

- 2022.11 ChatGPT——自然语言成为通用计算入口
- 2023 GPT-4 / Claude 2——复杂推理与长上下文加速成熟
- 2024 Claude 3.5 Sonnet / GPT-4o——稳定理解代码、图像与工具
- 2025.02 Claude Code——Agent 进入真实代码库与终端
- 2025.05 OpenAI Codex——云端并行完成软件工程任务
- 2026.06 Claude Fable 5——Agent 编排与长任务能力继续增强

交互范式演进：对话 → 工具调用 → 任务执行 → 自主协作。

**Chat 模式 vs Agent 模式**：Chat 模式由人拆解任务、复制粘贴上下文、逐步问答推进、人负责执行与验证；Agent 模式由用户描述目标，Agent 读取代码库、调用终端与工具、生成并运行和修复代码。一句话任务 → Agent 完整执行链：Prompt → Context → Plan → Tools → Verify。

**开发者需要的"文档"也变了**：过去的知识写给人看（产品文档、API 文档、参考代码、论坛问答、示例工程）；AI Native 时代还必须让 Agent 可发现、可理解、可执行——Agent 原生资产包括 Markdown 上下文、AGENTS.md / CLAUDE.md、Skill 与工具描述、规则文件、可执行验证命令。从"信息展示"升级为"上下文注入 + 行为约束 + 能力扩展"。

**关键数据**（Coding Agent 增长）：84% 开发者使用或计划使用 AI 工具（Stack Overflow Developer Survey 2025）；51% 专业开发者每日使用 AI 工具（Anthropic Economic Index）；69% Agent 用户认为生产力提高；-19% METR 特定样本中实际变慢（边界条件）。结论：速度 ≠ 真实生产力——真正提速依赖上下文质量、工具接入与验证闭环，而非单纯模型更强。能力闭环：理解仓库 → 跨文件修改 → 调用工具 → 测试验证 → 代码评审 / PR。

## 问题：机器人开发为什么没有同步完成 Agent 化

软件 Agent 操作数字世界，机器人 Agent 必须跨越云、PC、板端与真实物理环境。

传统机器人开发流程：烧录镜像 → 连接设备 → 配置环境 → 编写代码 → 部署模型 → 验证功能 → 稳定性测试。这条流程多年没有根本变化；真正难的不是写一段代码，而是跨环境、跨设备、跨工具完成可验证交付。痛点：多窗口、多命令、多工具、多人工交接。

**机器人应用本质是一条云—PC—板端协同链**（一个机器人应用不是一个代码仓库，而是三类环境共同产出的结果）：

- 云（云端能力）：数据生成与治理、模型训练、仿真、量化与模型发布
- PC（PC 端能力）：开发环境与代码配置、设备连接与文件管理、终端与 VNC、部署与调试
- 板（板端能力）：驱动硬件、运行模型、任务执行、日志与状态回传
- 链路：云端产出 → PC 端承接与调试 → 板端执行与回传

**Agent 渗透机器人开发，要跨过两个核心问题**：第一层解决"工具能不能统一调用"，第二层解决"Agent 能不能统一理解并完成任务"。上层理解与规划，下层统一调用，中间以统一工具协议衔接。

- 问题一 · 开发工具统一：烧录、连接、文件、终端、IDE、VNC、监控、模型部署
- 问题二 · Agent 上下文统一：理解意图、设备状态、项目文件、知识与 Skill、持续规划、跨端工具、验证物理结果、沉淀能力

## 解决方案：AI Native 三件套

以 **Moss AgentEngine** 为中枢，连接云端 **RoboGo**、PC 端 **RDK Studio** 与板端 **Moss**，实现从一句话意图到真机执行与验证的全栈闭环。

### RDK Studio：面向机器人的 AI Native 工作台

把机器人开发工具与 Moss 对话式 Agent 放进同一个上下文空间。工作台三视角：① 左侧找功能（设备、烧录、终端、文件、代码、VNC、监控）；② 顶部看设备（连接状态与目标板卡一目了然）；③ 底部问 Moss（自然语言驱动工具，状态自动流转）。

四大能力区：设备（发现 · 连接 · 切换 · 恢复 · 状态检测）、开发（文件 · 代码 · SSH/串口终端 · VNC）、部署（镜像烧录 · 应用配置 · 模型下发 · 进程运维）、扩展（Skill 工坊 · 本地模型 Ollama · 板端 Agent 管理）。执行路径：连接设备 → Moss 检查 → 工具联动 → 结果报告。

### Moss：面向机器人开发者的对话造物 Agent

把"一句话意图"转化为跨环境规划、工具调用与物理验证。三大能力矩阵：

- **Agent 内核**：规划 · 多 Agent · 模型切换 · 长任务 · 记忆与恢复
- **机器人专属 Skill**：软硬件知识 · 开发流程 · 设备与模型工具封装
- **物理设备验证**：代码运行 · 硬件反馈 · 日志分析 · 失败修复 · 结果确认

Moss CLI：同时处理 Host Code · Host Commands · Board Diagnostics · Board Workflows。完整闭环：意图 → 规划 → 代码/配置 → 部署 → 真机执行 → 状态回传 → 自我修正 → Skill 沉淀。

### RoboGo：把云端复杂能力变成开箱即用的应用

不再从零搭建 GPU、数据、训练与量化环境，而是在统一云平台按需组合能力。能力分组：环境与算力、开发机与云桌面、数据与训练（数据管理 · 标注 · 图像生成 · 训练任务）、模型优化与部署（推理服务 · 量化工具 · 模型与资产管理）。

### 端云闭环

RoboGo 生产模型，Studio 承接设备现场：云端模型生产线与板端验证现场通过产物下发和验证反馈形成持续迭代闭环。云端路径：数据资产 → 云端训练 → ONNX 导出 → 模型量化 → .bin 发布；板端路径：连接设备 → 运行验证 → 调试闭环 → 日志与结果反馈（反馈回路）。

### 目标体验：一个会话，制作一个机器人应用

把工具链操作隐藏在 Agent 之后，让开发者从"操作设备"转向"描述目标"。用户描述："让机器人识别有人跌倒，语音询问是否需要帮助，并把异常事件上传到后台。" Agent 自动执行九步：01 选择模型/Skill → 02 生成应用 → 03 配置依赖 → 04 连接设备 → 05 量化部署 → 06 启动测试 → 07 分析日志 → 08 修复问题 → 09 输出验收结果。用户可见结果：应用工程、设备运行状态、验证录像/日志、可复用 Skill 与部署包。

## 案例

| 案例 | 需求描述 | 关键结果 |
|------|---------|---------|
| 01 板端实时检测 | 在开发板上运行 YOLO、查看实时检测效果 | 自动连接设备、调起相机，部署 YOLO11 并开启网页视频流；浏览器实时显示检测框，画面稳定 **30 FPS**，举起即识别 |
| 02 机械臂开发 | 用 NERO 机械臂把 RDK X5 的盒子搬到 S600 上 | 自动连接设备、调用工具，规划并执行抓取轨迹；全程 **29.5 秒**、行程 **98.9mm**、力控 **5.0N**，平稳无报错 |
| 03 机械臂进阶（四色汉诺塔） | 认出杆上的四色套环，从大到小叠到中间的杆 | 识别出红 64 > 黄 57 > 绿 50 > 蓝 44，规划五步搬运顺序，五步依次落位，蓝环封顶成塔 |
| 04 人形机器人 | 让机器人自行设计并演示一段展示动作 | 用关节接口编排勾拳、展臂、收势等连续动作，每步实时打印；涉及高风险写入，经人工确认后再驱动真机执行 |
