## 01 业务背景：AI 原生 Agent 的真正瓶颈——语义漂移

### 产品形态四级进化（本次锚定「AI 原生」）

「小批量 · 多品种 · 快换型」的制造现场，需要会理解、会决策、会执行的 Agent：

| 级别 | 形态 | 特征 |
|------|------|------|
| ① | 方案 | 以人为主，工具化交付 |
| ② | AI+ 产品 | Copilot：已有产品 + 插件式 AI，只给建议，不担责任 |
| ③ | AI 原生产品 ★本次锚定 | AI 优先重构流程：数据飞轮、智能体决策、持续进化 |
| ④ | 工业大脑 | 跨场景智能中枢（演进方向） |

从「给建议的 Copilot」到「重构流程的 AI 原生」——缺的不是模型，而是可信的语义底座。

### 三种典型「语义漂移」

工业 Agent 从 Demo 走向产线卡住的三种语义漂移：

1. **不懂行话**：LLM 不懂工艺术语——把「直通率」当「良率」，口径张冠李戴、数字无出处
2. **语境丢失**：跨智能体协同上下文丢失——A 说的「工单」和 B 理解的不是一回事，协同链路越长语义损耗越大
3. **知识腐烂**：知识库随版本「沉默腐烂」——工艺改了、文档没改，检索到的是过期知识，错得悄无声息

在「堆模型」上走弯路，不如先把语义底座建对。

## 02 方案选型：本体 × 大模型 × 多智能体

三条主线不是并列的三件事，而是一台机器的三个部件——**本体在最底层，为另外两条提供「地基」**：

| 主线 | 角色 | 职责 |
|------|------|------|
| 本体 | 语义底座（罗盘） | 定义对象、关系、指标口径；证据分层、可信可溯；为全局提供共享语义 |
| 大模型 | 大脑（动力） | 读懂多源多模态数据；语义归纳、命名与推理；只提议、不裁决 |
| 多智能体 | 四肢（执行） | 任务拆解、编排、协同；各司其职、结果互校；把决策落到产线动作 |

分工原则：**大模型提议 · 数据与标准把关 · 人审定夺**。飞轮：数据、模型、智能体。

### 本体角色再定义：工业 Agent 的「语义罗盘」

从知识图谱骨架到指引方向的罗盘，本体的三个新角色：

- **引导 RAG 检索**：以对象/关系/口径为锚点组织检索——找得准，而不是找得多
- **约束 LLM 输出**：输出必须落在本体定义的边界内——口径错了直接拦截
- **共享语义中枢**：多智能体读写同一套语义——「工单」在所有 Agent 里是同一个「工单」

为什么叫「罗盘」而不是「地图」：地图是静态的，画完就旧；罗盘是动态的，不论 Agent 走到哪个任务、哪条链路，都用它校正方向——检索时校正查询、生成时校正口径、协同时校正上下文。

### 什么是工业本体：同一份数据的三层建模

| 层次 | 解决什么 | 局限 |
|------|---------|------|
| 关系数据库 | 怎么存（字段与外键写死在库里） | 业务语义靠人记 |
| 知识图谱 | 怎么连（实例连成网、可查询） | 缺统一类型与约束 |
| 工业本体 | 怎么懂（带类型、有约束、挂指标） | 可校验、可推理、可追溯 |

示例（生产工单表：mo_no 工单号 PK、mat_code 物料码 FK、qty 数量）：工单 1023 执行于设备 E07、投产物料 M203、供应供应商 S11 → 工单对象、物料对象、过站事件、供应商角色、指标「直通率」（挂口径）、约束「工单须有供应商」。

数据库解决怎么存，图谱解决怎么连，本体解决怎么理解与运用——它是工厂里人和 AI 共用的「操作系统」。

### 三种路线对比

| 路线 | 结论 | 理由 |
|------|------|------|
| 纯 LLM | ✗ | 上手快、Demo 惊艳，但不懂工艺术语、幻觉不可控；结论无出处、追责无门；知识更新靠重训/重灌 |
| 纯知识图谱 | ✗ | 关系显式、可查询，但缺类型与约束、难校验；构建维护成本高；与 LLM 生成链路脱节 |
| 本体增强（本方案） | ✓ | 语义、约束、证据三合一：口径锚定真实库表；输出受本体边界约束；证据分层、可信可审计 |

判断不靠直觉：设计了 RAG / GraphRAG / Ontology-aware GraphRAG 三臂对照评测来验证（PoC 阶段）。

## 03 技术方案：半自动本体重构工作台

### 工程化三难与解法

| 难题 | 解法 |
|------|------|
| 本体构建成本高 | 半自动构建：五步成谱（多源接入→语义推断→标准对齐→证据校验→人审成谱），机器提议 + 人审定夺，建模效率 **10×+**（人工数月 → 自动数天） |
| 版本治理难 | 证据分层 + 版本快照（每个结论挂证据、可回放可审计；实线=已验证 / 虚线=候选）；飞轮可验收：标注 **≥10 条** → 触发本体/KG 更新 → 同题集重测变化 **≥1pp** |
| 产线实时性要求高 | 分层消费（高置信结论走自动链路，低置信进人审队列；查询走本体索引）；PoC 交付物推进中（2026 H2）：家电本体 v0.5 · KG ≥300 三元组 · MCP 协议草案 |

### 为什么必须「半自动」：人机协同构建本体

- **全人工 ✗**：知识工程师 + 领域专家逐表梳理——千表万字段梳理以「月」计；专家稀缺、成本高、难规模化；业务一变就过时
- **全自动 ✗**：大模型端到端直接生成本体——无外键、命名晦涩、语义隐含；易生成「幻觉关系」、结论无证据；开放场景至今无成熟端到端方法
- **半自动 · 人机协同 ★**：机器提议（多源多模态并行召回）+ 数据与国际标准双重把关 + 对抗校验；置信分层（高置信自动、低置信人审）——可回放、可审计，敢决策、能上产线

### 系统架构：本体重构工作台的四层设计

多源数据自下而上逐层加语义，全程可治理、可追溯，按 W3C 国际标准对外导出（OWL2/RDF、SHACL、SKOS、JSON-LD、SPARQL）：

- **L1 数据层**：业务数据库、数据仓库、工业代码、指标看板、文档图纸、现场 IoT、业务 API、REST API
- **L2 引擎层（确定性 DAG × 多体）**：语义理解（多源采集·语义推断·事件识别·关系发现·场景切分·动作识别）、知识建模（指标关联·层次发现·标准对齐·命名治理·需求建模·图谱装配）、可信治理（证据校验·对抗审查·人审闸口·对话式编辑·质量门禁·版本发布）——3 组 18 项能力，每步纯函数可缓存回放，抽取器后接独立审查 agent
- **L3 图谱层（IR 中枢）**：单一真相源——6 类元素 + 7 项可信机制；对象、关系、事件、指标、动作、场景；可信分层、证据挂载、缺口清单、版本快照、G6 可视化、双语标签、本体库
- **L4 应用层**：智能问数、质量追溯、排产调度、智能体决策、数字孪生（9 大场景）、开放服务

贯穿治理·安全：证据溯源、可信分层、人审兜底、版本管理、反造假校验。LLM 按任务选模：deepseek-v3 建模、qwen3-coder 代码、gpt-5.x 对抗校验。

### 工作台工程实现：Cosmo DataMind（自研 PoC 原型）

Flask 单端口（:8092、82 路由、before_request CSRF 守卫、统一错误/写守卫/路径防穿越）+ 原生 JS 单页（27 模块 hash 路由、G6 图谱、ECharts、统一助手 $/esc/J 全站 XSS 转义）+ 本地只读 SQLite（ro_connect(mode=ro) 三重防写；IR 存储 _atomic_json + _WRITE_LOCK；引擎 agent_runtime → hermes / claude-code 离线降级）——每步纯函数、LLM 缓存，全栈可回放、可审计。

- 构建链：_gather_evidence → _llm_extract → _adjudicate_ir → _llm_semantic_review → 落盘（三级控制环）
- 问数链：build_context → agent_sql_plan → q() → narrative（本体上下文 → 可执行 SQL → 带来源叙述）
- 导出链：_ir_to_turtle → SHACL / HermiT（IR 单一真相源 → OWL2/RDF 确定性导出，无 LLM）

PoC 首跑（imom 数据集 · 212s · 实验室）SSE：intake → intent → gather_evidence → llm_extract → semantic_review（16 通过）→ verify（15 verified / 1 candidate）→ narrate。

质量门：109 集成断言（每路由 happy + 边界 + 安全）、构建产物过 SHACL/HermiT、pyflakes 零告警、完备度记分卡量化可审计。

### 建模思路：五步成谱，步步留痕

① 多源接入（库表/代码/看板/文档）→ ② 语义推断（对象·关系·事件·指标）→ ③ 标准对齐（ISA-95 / UFO、OWL2 / SHACL）→ ④ 证据校验（交叉印证·分层、对抗审查）→ ⑤ 人审成谱（专家确认、导出图谱）。

建模哲学四条原则：**半自动更契合工业**（机器提议 + 人审定夺，兼顾质量与效率）、**复用优先**（能对齐既有国际标准/本体就不重复造轮子）、**需求驱动**（从真实业务问题出发，划定范围、定验收标准）、**可信可溯**（每个结论都挂证据，按可信度分层、可校验）。

### 构建流程：八步确定性 DAG

编排器跑固定 DAG（非自由 agent 自调度），节点间只传 IR，每个 agent = 纯函数步 (IR_in, ctx) → IR_out：

① 采集（双流并行：DB 流结构·分布 + 代码流 AST·JOIN·注释）→ ② 双源融合（冲突裁决：代码 JOIN > 命名）→ ③ 归一·切分（Louvain 社区、6–12 场景、拼音→中文）→ ④ 抽取（对象∥事件∥动作）→ ⑤ 关系抽取（取值重叠 ≥60% 且列名有据）→ ⑥ 对抗审查（每个抽取器后接独立审查 agent，多数否决→重抽）→ ⑦ 完备性批判（三覆盖率 ≥90%、loop-until-dry、缺口→gap_list）→ ⑧ 人审闸口 → 发布（任意闸口可暂停、草案可撤销、导出 OWL2 / SHACL）。

工程铁律：LLM 缓存（同 prompt+model 命中）→ 全流程可回放；人审是一等公民，任意闸口可暂停；失败不阻断——单表/单 agent 失败降级 candidate / gap，不静默丢，前端可见。

**证据分层**（可信度只由证据决定，不由结论需要决定）：verified 实线（重叠 ≥60%）· asserted 短虚（人工）· gap 点虚（未过）· inferred 预留（规则）。

### PoC usecase：把无外键的脏数仓建成可信本体

输入：海尔卡奥斯离散制造数仓——无外键、拼音列名（pm_mo_number）、无注释的真实数据。

1. **关系发现：用数据自证，不让 LLM 凭空造**。overlap = |distinct(子) ∩ distinct(父)| / |distinct(子)| ≥ 60% = 1:N；子键必须非唯一（排除 PK）、父键必须唯一（≥0.95）；列名一致性打分（同名/含表名才可信，无据 → candidate）；先 AST/静态解析锚点、后 LLM 语义——绝不冒充 verified
2. **时间窗口证伪：警惕「假高重叠」**。同一对列单日窗口 100% 重叠、近一月窗口跌至 3.4%；窗口不足一律降 candidate；足够窗口下找回 3 条未被外键记录的真实关系
3. **输出：IR 证据分层 → G6 本体图谱**（工单、物料、设备、供应商；投产、执行于、供应?）。IR 库 5 主表 + 证据库 onto_evidence（每点可溯源 db/code/kpack/human）

诚实边界（开发者最认这一条）：**指标覆盖率 18.8% 未达标 → 以「基线本体 + 显式 gap 清单」发布，不灌水**；当前代码证据仅 1 列（joins=0），「双源」目前其实是「1.x 源」——如实写明，待业务代码接入后双源裁决生效。

### 多智能体协同框架

| 能力 | 做法 |
|------|------|
| 任务调度 | 把业务目标拆成任务图，按依赖与优先级派发 |
| 智能体编排 | 确定性 DAG 编排，每步纯函数、可缓存回放 |
| 记忆与技能复用 | 跨任务记忆、技能沉淀——一次学会、多处复用 |
| 对抗校验 | 关键步骤后接独立审查智能体——默认怀疑、只降不升 |

本体在协同中的位置：任务调度读本体（知道「这个指标归哪个对象、由哪些表支撑」，才能拆对任务）；智能体间传的不是自然语言，而是本体上的对象与关系——上下文不再漂移；记忆挂在本体节点上——版本更新时过期知识可定位、可替换，不再「沉默腐烂」。数据智能方向构建 4 类 Agent：本体构建、工艺问答、换产辅助、决策辅助（面向创智 PCB、空压站场景）。

### 本体增强 RAG：幻觉抑制的实证

无本体（✗）：把「直通率」当「良率」、猜表猜字段、口径张冠李戴、编造看似合理的数字——答案无出处，不敢用。本体接地（✓）：给出「直通率」的口径定义、顺工单→产线关系锚定真实库表、答案附来源、可追溯、可审计。

三臂对照评测设计（问答准确率 · PoC 验收线）：Vanilla RAG ≥60%、GraphRAG 对照臂、Onto-GraphRAG ≥65 70%。说明：本体增强 RAG PoC 评测在实验室进行、尚未在生产平台验证，检索、幻觉抑制、问答准确率的提升为方向性结果。

### 一个来自产线的问题（SUV-3 焊机）

「SUV-3 焊机最近一周废品率从 0.8% 上升到 2.3%，可能是什么原因？」

① 本体识别意图（实体：SUV-3 焊机；类型：质量异常 · 工艺域：焊接）→ ② KG 关系链召回（沿「设备 → 参数 → 缺陷模式」召回历史案例与关联参数）→ ③ 约束下生成（本体 schema 约束输出：3 个可能根因 + 检查清单 + 复核建议）→ ④ 反馈写回（工程师点「正确/需补充」→ 触发 KG 写回与本体迭代候选）。

PoC 示意场景（离散制造 · 实验室验证，尚未上线）。答案不再是「一段像样的话」，而是挂着证据、可以照单排查的行动清单。

## 04 样板场景：行业本体 → 产线可信 Agent

### 电子制造：从问数到根因，指标说话

- **智能问数**：业务人员直接开口问，无需懂表结构与 SQL；本体定位对象、关系与指标口径，把问题翻译成可执行查询；答案带来源与口径，支持下钻
- **质量追溯**：不良记录 → 在制品过站 → 生产工单 → 物料 → 供应商，一条不良记录秒级回溯、精准定位根因；为质量、排产智能体提供可信上下文；处置建议可执行、可追责
- 场景价值目标（行业参考 · 示意，非本方案落地）：产品不良率 ↓10%、交货周期 ↓20%、注塑调参周期 ↓90%+、培训成本 ↓75%

### 能源行业：能碳管理

能碳智能体集群（能耗监测 · 碳排核算 · 优化调度，覆盖厂区到产线，空压站等公辅能效场景）；能碳大模型 + 电价预测大模型（负荷预测与电价预测联动、错峰生产、削峰填谷；源网荷储控贯通、三网合一、四流融合）。本体的作用（目标）：统一「能耗口径」——每一度电、每一吨碳算得清、对得上、追得到。说明：能碳平台为卡奥斯已有能源产品；本体在此的角色是「统一能耗口径」的语义底座（目标场景，本体方案为 PoC）。

### 智能体阵容（卡奥斯制造与能碳两大智能体集群）
