# 金融营销 AI 合规审核（腾讯）：从审核工具到自进化合规智能体

2026 Agent 大会「金融场景Agent实践论坛」演讲《从审核工具到自进化合规智能体——金融营销 AI 合规审核的架构升级之路》，演讲者巫晓杰（腾讯高级工程师，2026 年 7 月）。

## 01 DEFINE 现实问题

### 风险不只藏在文案里，也藏在审核流程里

两个公开监管案例揭示金融营销审核的两类典型失效：

- **案例 A · 流程缺位**（来源：广西证监局公开案例）：宣推海报未经有效合规把关——海报发布前未经合规意见把关（审核流程）、必要风险提示缺失（风险揭示）、审核人员不具备相应业务资质（人员资质）。监管结果：出具警示并要求限期整改。
- **案例 B · 选择性披露**（来源：重庆证监局公开案例）：只展示亮眼业绩，隐去完整表现——刻意突出局部或短期亮眼业绩（数据呈现）、未同步披露产品完整历史表现（信息完整性）、可能对投资者形成不当收益预期误导（投资者认知）。监管结果：出具警示并责令整改。

结论：**金融营销合规不是一次"文字检查"，而是一条覆盖内容、数据、主体与流程的证据链**。

### 素材从文案扩展到直播，传统审核为什么失效？

输入端素材形态与数量持续扩张（① 文案：客服消息、App 弹窗，难点语言语义理解；② 短图：海报、Banner、开屏图，难点图文复合关系；③ 页面长图：落地页、产品介绍页，难点长上下文关联；④ 视频/直播：广告、投顾直播、短视频，难点实时多模态风险），处理中线性人工流转（接收素材→排队分派→人工判断→抽检/复核），输出端三重结构性瓶颈：

- **覆盖不足**：抽检为主，大量素材处于审核盲区
- **响应滞后**：平均滞后天/周，风险识别落后于素材投放节奏
- **判断不一**：不同审核员对同一素材的审核结果存在差异
- **新规迟滞**：监管趋严、整改窗口收紧，新规发布后审核标准落地存在空窗期，人工易按旧经验误判新边界

素材复杂度 × 线性人力流程 → 传统审核无法同时满足"全量、实时、一致"。

### 重新定义合规审核系统的能力

| 业务目标 | 系统能力 | 智能体要素 |
|---------|---------|-----------|
| 看得全（多种素材统一接入） | 感知与工具 | 多模态理解（OCR/VL/ASR）、工具调用 |
| 判得快（审核前移到发布前） | 规划与路由 | 任务拆解、场景识别、规则按需加载 |
| 判得准（结论稳定且可复核） | 推理与验证 | 规则知识库、证据定位、反向验证 |
| 跟得上（持续响应规则变化） | 记忆与演进 | 规则/模型双轨演进、案例记忆、法务反馈 |

## 02 DESIGN 系统与工程

### 金融营销合规审核智能体框架

完成"看懂—匹配—推理—验证—输出"，离线持续优化规则与模型：

- **能力支撑层**：感知解析（图像/文本/视频、场景与主体识别）、规则与策略（合规规则库、场景化审核模板）、工具调用（OCR/VL/ASR、MCP 查询、证据定位）、合规推理（风险推理·等级、修改建议）、知识与记忆（法规·案例·版本、历史审核与反馈）
- **在线审核主链**：待审素材 → 多模态解析 → 主体与场景识别 → Skill 规则路由 → 风险推理 → 证据锚定/反向验证 → 结构化输出（输出：风险标签 · 风险等级 · 违规证据 · 依据条款 · 修改建议）
- **持续演进**：规则 Skill 化治理（规则规模扩大后如何找到正确规则——解决"如何找到"）、合规规则自进化（线上错误如何快速转化为规则修正——解决"今天怎么改"）、模型双轨数据飞轮（真实反馈如何沉淀为模型长期能力——解决"明天变成本能"）

### 感知解析：长图解析（三阶段工程流程）

**核心问题**：如何在保留图像信息、文字位置关系的同时，完整准确地提取长短图中的全部内容？合规感知要求三项缺一不可：内容完整（底部小字、表格数据不能遗漏）、视觉语义（理解图表、产品卡片与配图）、空间关系（保留数据、提示与按钮的位置）。

两种方案的问题：纯 OCR 方案仅提取纯文本、缺失视觉元素、丢失文字空间位置关系（审核缺失"视觉层"信息）；多模态模型识别关键信息遗漏（底部小字、表格数据）、模型产生幻觉虚构不存在的文字、复杂表格/图表结构无法完整解析（根因：当前多模态模型对长图的训练语料严重不足）。

**三阶段方案**：① 语义切图（视觉边界+背景变化+OCR 文字框，生成语义连续切片，相邻切片保留重叠）→ ② 切片识别（逐片输入多模态模型，提取文字、图表、图片元素及其位置关系，同时识别推理视觉类合规风险）→ ③ 全局合并（原图坐标排序、重叠去重+语义拼接，恢复页面结构，输出结构化图文内容）。

**关键结果**：

| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| 召回率 | 90.15% | 97.59% | +7.44 个百分点 |
| 漏字率 | 9.85% | 2.41% | 下降 75.5% |
| F1 | 94.73% | 98.67% | +3.94 个百分点 |
| 平均耗时 | 16 秒 | 21 秒 | 增加 5 秒 |

**对于合规审核，真正高成本的不是多花 5 秒，而是漏掉底部的一句关键信息。**

### 规则与策略

**合规规则从哪里来（三层法规底座 + 动态监管信号）**：

1. 基础法律（稳定底座）：广告法（极限用语、保本/保收益承诺）、反不正当竞争法（虚假或引人误解的商业宣传）
2. 金融行业规则（转化为审核细则）：金融产品网络营销管理办法（全链条责任）、基金销售监管办法（销售责任、前置审查、业绩展示、风险揭示，2026-09-30 施行）、基金宣推规定
3. 内容与 AI 治理（AI 新增）：网络信息内容生态治理规定（平台责任、不良信息治理）、人工智能内容标识办法（显式+隐式标识，2025-09-01 施行）

动态监管信号：整合监管通报、处罚案例及行业自律规则，细化执法边界与例外条件，持续更新。规则入库必带字段：法规/文号、条款原文、适用主体与场景、生效状态、版本与案例依据（可追溯、可更新、可执行）。

**为什么法规原文不能直接用于审核**（法规原文的执行断点 → 对应工程改造）：

| 断点 | 问题 | 工程改造 |
|------|------|---------|
| 过长且分散 | 多法规、交叉引用和长上下文导致注意力稀释（字数 10w+） | 映射：按主体、产品、渠道与时间，只加载有效相关条款 |
| 执行边界抽象 | "醒目、误导、适当"等原则缺少可计算标准 | 原子化：拆成主体、行为、对象、条件、例外和可测阈值 |
| 适用范围不清 | 什么主体、行为、对象和场景适用，原文难直接映射 | 范围界定：构建适用条件（主体×产品×渠道×受众×行为） |
| 缺少执行结构 | 没有证据要求、排除条件、判定状态与处置路径 | 决策：定义排除条件、证据要求及五态判定与人工路由 |
| 版本与口径漂移 | 新规生效、条款冲突和监管案例持续改变边界 | 发布：正例/反例/边界例验证，审批后版本化上线 |

**合规规则 = 来源 + 适用条件 + 必须/禁止 + 排除条件 + 决策条件**。

**金融宣推合规审核体系（标签体系负责路由，结构化规则负责判定）**：风险标签体系（以基金宣推为例）：① 宣传文案表述（最高级与极限表述、娱乐化用词、收益承诺、时间限制、数据支撑）；② 基金历史业绩展示（历史业绩展示、年化收益数据、盈利概率、测算模拟数据）；③ 指数/其他数据展示（数据来源与风险提示、指数回测模拟数据、不当类比）；④ 信息披露及风险揭示（销售服务主体与风险提示、特定事项风险说明）；⑤ 违规介入持牌业务（证券投资咨询、基金评价、基金投顾、基金销售宣推）。示例（待审文案"长期稳健增值，稳赚不亏"）：来源《广告法》第 25 条、内部风险定义 v7.2；适用条件：基金代销机构/基金管理人/平台方、基金宣推或一般金融营销；必须合理提示风险，禁止保本、零风险、稳赚、不会亏及未缓和的收益承诺；排除条件：仅用于说明基金经理投资理念或产品策略（例如"更关注持有人体验"）；决策条件：命中禁止条件且未命中排除条件 → 不通过/整改风险。

**审核体系 SKILL 化治理（两级渐进式披露结构）**：传统方式将所有规则不加区分地拼装进每次推理，规则库规模扩张线性推高 Token 开销、Prompt 冗长导致模型注意力分散。Skill 化方式：每个风险为独立 Skill 单元，风险规则核心定义常驻 Prompt；边界、例外情况、历史案例等按需注入。收益：支撑规则库持续增长而单次推理开销不线性增加、模型高度聚焦、降低 Token 消耗提升端到端响应速度。

### 工具调用：如何生成可审计证据？

**同一句宣传文案，因产品事实与数据时点不同，可能得到完全不同的审核结论**（"固收+策略，点击查看"示例）：

1. 输入端（素材事实相同）：感知解析与 MCP 查询要求——产品名称/代码、宣传说法（固收+）、法规要求（根据 2022 年相关监管窗口指导，'固收+'产品宣传需结合权益投资比例及产品合同约定判断，仅当基金底层权益资产占比 10%-30% 时才可用'固收+'宣传）、需要查询基金实际持仓中股票占比数据
2. 处理中（生成外部证据）：实体消歧（代码·份额·产品状态）→ 工具规划（数据源·查询字段·有效时点）→ MCP 查询（参数化调用外部数据接口）→ 结果校验（类型·单位·范围·来源）
3. 输出端（结论因证据而异）：产品 A 事实满足当前审核口径→通过；产品 B 事实超出审核边界→驳回；数据不可用（超时/缺失/来源冲突）→复核

**证据快照**：时间戳·工具版本·原始响应，证据对象必带来源、时点、版本、快照；结构化证据绑定规则，不直接拼接自由文本。公式：**素材事实 + 外部动态事实 + 适用规则版本 → 可追溯的合规结论**。

**合规判断不是终点，证据才是可交付物**——把语义结论反向映射到原图坐标，形成可验证、可修正的合规证据链：

1. 生成证据目标（"稳稳增值"或指定视觉概念）
2. 证据类型路由（文字｜视觉对象｜不规则区域）
3. 专用定位（字符框｜开放词汇对象框｜像素轮廓；技术：EasyOCR/CRAFT、Grounding DINO、SAM）
4. 一致性验证（内容、坐标、规则结论相互支持）
5. 失败降级（无法定位或冲突 → 人工复核）

## 03 BUILD 模型训练

### 自研模型：小参数、高准召、低时延

通用大模型的"通用能力"恰恰是垂直低容错场景的负担。四大痛点：

- 准召精度过低：通用模型准确率/召回率 **30%-40%**，在垂直合规风险识别任务上无法支撑高容错要求
- 时延高、资源消耗大：开源大参数模型单次推理 **128s / 16 张 GPU 卡**，部署门槛极高，不适合规模化审核生产
- 无法定制高召回诉求："宁可错杀不可放过"，完全依赖模型自身指令跟随能力业务错配，无法通过硬约束满足特定业务级高召回要求
- 长上下文定位不足：审核 Prompt 平均长度 **15k token/条**，模型容易忽略材料重点，导致合规审核疏漏

方案：以面向合规任务的专项模型，针对高准召、低时延与长上下文定位进行针对性优化。

### 模型训练的技术方案（三阶段）

1. **数据合成**：营销素材法律风险合规数据合成需求三部分——指令微调（SFT）正向与反向合成数据、强化学习（RL）策略优化与合规对齐。反向合成：金标种子数据 → 修正为无风险文本 → 标签匹配与场景泛化 → 新风险合规指令数据（通过金标数据的风险标签修正原始识别结果，结合随机匹配实现场景泛化）；正向合成：无标注原始图片 → OCR 文本化与风险/长图拆分 → 多模型打标 → 合并推理结果（通过预处理降低合成难度，集成不同表现的模型进行打标合并，显著提升数据标注准召率）。RL 数据：基于 GT 构建 Pair 偏置数据驱动奖励模型精准评分（正例=完整合规四元组/无风险；反例=遗漏/错判/编造风险）。
2. **指令微调（SFT）**：基于正/反向合成数据增训，形成专项任务基座，支持快速迭代（开发难度较小，效果见效快）。
3. **奖励模型 & 强化训练（RL）**：构建 Model/Rule 双类奖励模型（开发难度较高，具备较大业务潜力与判别精度），形成风险合规专项强化 F1 模型作为最终业务产出模型。底座：自研金融基座（基于海量法律金融文本训练，深度语义理解、严谨逻辑推理与指令遵循能力）→ 通用金融 F1 模型 → 风险合规增强 F1 基座 → 风险合规专项强化 F1 模型。SFT-RL 内部闭环训练，以小参数量实现高准召率、缩短推理时间，满足快速投放需求。

**SFT/RL 的组合提升：三个关键决策**：① 数据配比（覆盖分布：原生/合成、有风险/无风险全覆盖；兼顾长尾：热门与冷门风险共同采样；避免偏置：不让单一风险类型主导训练）；② 轻量 SFT（学会任务：理解审核要求与结构化输出格式；控制强度：仅做轻量训练避免死记硬背；保留推理：为后续 RL 阶段留出探索空间）；③ Pass@8 选基座（不只看 Pass@1：单次成功不代表模型推理上限；评估探索上限：用多次采样观察模型潜在能力；选择更高天花板：为 RL 阶段提供更大优化空间）。

**loss 优化（F2 loss）**：营销场景风险审核需要高召回，并不符合常规的 reward loss 设计。常规的 F1 loss（β=1）只能牵引被召回风险样本的准确率，提供作弊空间；现改为 **F2 loss（β=2）四倍放大召回权重**，满足风险业务的严格审核需求（Offline Policy：在有风险样本的统计中做 RL）。

经验结论：训练稳定性不是某个算法单点决定，而是数据、SFT 强度与基座选择共同作用的结果。

## 04 EVOLVE 自进化与结果

### 合规规则自进化（小时级）

解决规则变动响应慢、人工维护成本高的问题。闭环架构：误判+漏判累积、主动扫描监管通报（预判规则变更）、冲突检测与识别（识别存在冲突的规则）→ ① AI 自动归纳（存在"规则未覆盖"→建议新增规则；"例外情况"导致的误判→建议补充例外；"规则边界模糊"导致的不一致→建议细化边界）→ ② 法务人工确认（确认→直接写入规则库；修正→调整后写入；驳回→标注原因供 AI 下次避免）→ ③ 规则库更新 & 即时生效（新规则写入 QA 知识库→推理时动态拼装进 Prompt→下一次审核即包含新规则，无需重新训练模型）。

### 双轨自进化（规则轨快轨 + 模型轨慢轨）

问题回顾：此前 RL 训练信号主要来自静态历史 Case 和模型集成打分，本质接近"规则型训练环境"，反馈保真度有提升空间。解决方案：将线上法务复核实时反馈系统性接入，法务的"确认/修正/驳回"标签同步反哺 RL 再训练，实现快慢结合、浅深互补。

- **规则轨（快轨）**：法务反馈直连 → 规则库 Skill 实时更新 → 小时级全局生效。定位：快速修正、浅层技能
- **模型轨（慢轨）**：沉淀为强化学习信号 → 周期性 GRPO 再训练 → 模型深层能力转化。定位：周期沉淀、本能进化

**规则自进化解决的是"今天的问题今天能改"，模型自进化解决的是"今天的经验明天变成模型的本能"。两条轨道共用一个数据源，这才是真正的自进化系统，而不是两套各自为战的补丁机制。**

### 效果与结论

| 维度 | 优化前（Baseline） | 优化后（Target） |
|------|-------------------|-----------------|
| 审核覆盖率 | 抽检 | 全覆盖 |
| 审核周期 | 3-5 天 | 分钟级 |
| 大模型准召 | 约 30%-40%（通用模型） | 召回率 95%+ / 精确率 80%+ |
| 单次推理耗时 | 128s（671B 模型） | 40s（自研 32B 模型，耗时降低约 69%） |
| 部署算力 | 16 张 GPU（DS 模型为例） | 节约 75% 成本 |
| 规则更新周期 | 人工维护，周级以上 | AI 辅助归纳，小时级生效 |

三条结论：**小模型胜大模型**（垂直场景下，专项小模型+精细化 Loss 设计比通用大模型更有效，重点在于解决训练范式与目标函数问题，而非参数规模）；**Harness 优于 Prompt**（将工程投入转向"设计 Harness"收益更大，Skill 化治理、证据锚定系统性提升了可靠性，无需改动核心模型代码）；**人机协同自进化**（真正的自进化系统是"AI 提建议、人做决策、系统记录留痕"，通过快慢两条反馈轨道共享真实反馈源，实现闭环演进）。
