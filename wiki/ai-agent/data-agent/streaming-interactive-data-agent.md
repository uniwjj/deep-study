# 流式交互与实时洞察：Agent 架构如何提升数据产品的实用性

> 演讲者：许鹏，2026 Agent 大会「面向Agent的数据架构论坛」（DataFun 超级智能体系统架构峰会）
> 主题：从能聊，到能信、能改、能积累
> 目录：01 价值模型 · 02 工程支撑 · 03 上线验证

## 01 价值模型

### Part 1：可信、能干活——准确永远是第一位的，但只有准还不够

- **问题**：业务要「分析做完、材料交出去」；团队却停在「把单次回答做准」——准是底线，不是终点
- **表象**：演示惊艳，试两次就走；或当高级搜索，不进入工作流
- **原因**：把数据分析当 QA，不是多步工作流；可信没打底，或缺交付、多轮、沉淀
- **应对**：用五层价值模型重定义成功标准，架构按层投资

### 五层价值模型（全文锚点）——底层不满足，上层没有意义

| 层级 | 定义 |
|------|------|
| **可协作**（第 5 层） | 团队能复用、口径能共识、产出可审计 |
| **可积累**（第 4 层） | 偏好被记住、配方可复跑、越用越省力 |
| **可参与**（第 3 层） | 口径能确认、中途能纠偏、多轮能深入 |
| **可消费**（第 2 层） | 报告拿得出手、图表能导出、材料可再编辑 |
| **可信**（第 1 层） | 数字有出处、过程可见、结论有边界 |

「可信」的第一杀手，往往不是模型笨——**是等待。等得越久，越不信。**

### 价值支撑①：流式 + 可信——永远有反馈 + 不依赖 LLM 自判

**流式交互**：Agent 先启动，取数异步——秒级回应；进度/工具/执行片段流式推送——全程有进展；后台不中断，按序号断点续传——断了能续（回扣价值层：等待消磨信任）。

**可信机制：规格自审 + 平台约束**：
- 规格层：定稿前自检；结论须绑定查询依据
- 平台层：沙箱隔离、权限网关、数据扩面审查
- 样本不足/口径冲突 → 收缩结论或请用户确认
- 低置信场景 → 交给用户拍板，不替用户做决定（回扣价值层：看起来对更危险）

原则：系统给建议选项，不限制用户表达。**该人拍板的地方要让渡。**

### 价值支撑②：水下积累——没有水下积累，Agent 只能是花瓶

- **问题**：功能上线后体验不再变好；每次像第一次见面
- **表象**：第一次惊艳，第三次冷淡；口径偏好反复解释
- **原因**：只投可见功能；元数据与行为抽象未同步深化
- **应对**：鸭子浮水——水上交付，水下积累

水面之上：流式进度、图表、报告、多轮追问、关键节点确认。水面之下：语义层、偏好、纠偏、配方库。行为 → 沉淀 → 更懂他 → 反哺。飞轮：**第 N 轮沉淀 = 第 N+1 轮起跑线**。

### 水下①：元数据——元数据是地基，不是附属品

- Before：用户问「按渠道看留存」——系统不知道渠道对应哪张表哪个字段，只能猜
- After：字段语义已在数据目录对齐；分析前检索注入——第一次探索，第十次惯例
- 映射示例：字段-业务术语（channel_src = 渠道来源）、指标-标准口径（留存 = 次日仍活跃，不让模型猜）、维度-业务粒度（渠道 = 一级/二级枚举）

让 LLM 在「对的世界」里讲话——**不该让模型出错的事，从模型职责里移走**。

### 水下②：行为抽象——用户不配置，系统从行为里学

- Before：第三次纠正 channel_source vs utm_channel，第四次还来
- After：纠偏进入偏好；下次「渠道」默认 channel_source，口径变更时再确认
- L1 私域校准：用户纠偏口径仅影响自己会话，立即生效
- L2 群体共识：多用户独立做出相同校准，审核后升级组织口径

沉淀物：偏好、纠偏、配方。

## 02 工程支撑

### 质量标准：一次「好」的分析——六条过关线

① 数据源准确（问 GMV 就用 GMV 口径）② 方法恰当（问环比不给趋势糊弄）③ 代码正确（SQL/Python 经得起推敲）④ 解释贴近生产（具体数字，非「呈下降趋势」）⑤ 过程透明（用哪张表、什么口径可见）⑥ 路径可复用（下次一键召回，飞轮）。①~⑤ = 这一次过关，⑥ = 下一次更省力。

### Spec Driven：把「怎么分析」写成规格，而非巨型 Prompt

一句话：规格可版本化、Agent 执行规格、用户行为迭代规格。

| Prompt Driven | Spec Driven |
|---------------|-------------|
| 临场编方法论 | 阶段与交付契约固化 |
| 成功标准在模型脑子里 | 成功标准可检查、可演进 |

### Skill 落地：把规格写成可执行的 Playbook

不是一大段 Prompt，而是可版本化的分析能力包——流程、规则、约束分开写，按需加载：

1. **流程规格**：意图对齐 → 取数验证 → 报告定稿 → 后续推荐
2. **按需加载**：到节点才读对应规则片段——防跳步、控上下文、不靠模型自律
3. **运行时约束**：工具白名单、证据链、handoff、断言门、HITL（Human-in-the-loop）

把六条过关线写进阶段契约。核心：不是靠模型「记住」，是靠系统 enforce。投产后像软件维护 Skill：评测、门禁、发布，用户反馈持续写回规格。

### 准确性：从 Text2SQL 到 Text2Code——表达力质变

- **起点 Text2SQL**：不把数据丢给 LLM 算——让 LLM 生成 SQL，计算交给确定性引擎；白盒可验证、不会瞎编数字
- **边界：SQL 表达力不足**：归因分析、数据特征统计、分布/相关性——纯 SQL 极其费力或无法表达（巨型嵌套子查询、复杂统计写不动）
- **演进 Text2Code**：LLM 生成 Python 在沙箱执行，复用成熟数据分析生态（pandas / statsmodels / scipy），依然白盒可验证

关键守住的底线：从 SQL 到 Code，**白盒可验证从未放弃**——代码可见、过程可追溯、结果可复现。

### 行为学习：用户画像——从会话蒸馏，下次自动召回

原则：存「学到了什么」——常用表/指标、分析方法与路径、口径偏好——不是复述聊天记录。

- **已落地·AGNO 双轨学习**：在线（结构化画像 + 主题记忆注入每轮分析）；离线（历史提问批量蒸馏，定时更新偏好）。画像：角色、业务域、区域、图表偏好；记忆：分析习惯、关注指标、口径定义、输出风格
- **探索中·HINDSIGHT 语义记忆**：Retain（会话阶段性沉淀事实——表/指标/纠偏）、Recall（提问时静默召回相关偏好与路径）、Reflect（需综合画像时聚合口径与习惯）；画像分面：表约定、指标口径、交互风格、分析启发
- 学什么（常用表、核心指标、筛选习惯）→ 怎么学（分析路径、对比维度、统计方法）→ 怎么用（下轮默认口径，少重复确认；配方可复跑）

回扣「可积累」——承接「水下②行为抽象」，技术层把偏好变成可召回资产。

### 语义资产：元数据不是一次性导入——是 Agent 辅助的持续整理

原则：Agent 编排证据、生成候选；**业务口径须人审 verified**——不凭空把字段标成指标。

- **两类语义资产**：数据资产画像（物理层字段分类、候选指标、血缘、风险点）；数据集画像（报表/看板粒度、口径、底层映射、使用足迹；双向关联——从看板下钻到表、从表上钻到可执行入口）
- **分层生产，不全量深挖**：轻量登记（全量资产索引、路径、归属、主题）；深画像队列（按优先级择优生成完整语义说明——优先级 = 使用热度 + 语义密度 + 人工 boost；高热低语义工程表：登记即可，不浪费深画像成本）
- 采什么（目录、血缘、消费足迹、术语库）→ 怎么写（有证据→正文，不确定→待确认，无证据不写事实，不读真实数据样本）→ 怎么用（draft → verified → 运行时召回；个人偏好可反哺组织）

回扣「水下①元数据」——把目录从静态注释升级为可审核、可演进的语义资产。

### 架构全景：数据流与模块边界

- 【触达】Web 主站 / IM 机器人 / 对外 MCP；流式通信层（SSE、续传、过程事件）
- 【会话】Agent 编排（主 Agent、子 Agent、LLM；生命周期、压缩策略、分支回放、事件总线、回调分发、前端、域语义）
- 【Spec】技能库
- 【水下】自进化层：知识、记忆、画像（沉淀、召回）
- 【数据核心】DuckDB 沙箱、版本管理（报表按权限加载）；OLAP 路由/企业数仓
- 【工具】查询、Python、图表；飞书/PPTX 导出
- 安全审计全链路（输入、报表、底表、SQL）

## 03 上线验证

### 度量规格：产品健康度——四层度量体系

好产品运营出来的；硬核能力也是度量驱动、规格迭代长出来的，不是 Day 1 设计图。

| 指标 | 定义 | 好 |
|------|------|-----|
| ① UV/PV | 独立用户、访问/会话次数 | UV 稳增、PV/UV 升 |
| ② 追问率 | 同会话 ≥2 轮提问的占比 | 高于单次问答基线 |
| ③ 渗透率 | 活跃 UV ÷ 目标用户池 | 逐季提升、跨部门扩散 |
| ④ 留存率 | N 日/周 cohort 留存、滚动活跃率 | 曲线趋平、cohort 改善 |

核心行为指标之外，探索从会话历史做隐式满意度评分，补「完成但不满」的盲区。

### 效果·价值对应（数字挂回五层模型）

- UV/PV 升 → 规模触达、产品被看见 → ③ 可参与入口
- 追问率 69% → ③ 可参与 + ① 可信（流式 + 白盒，愿深聊）
- 渗透率升 → ⑤ 可协作、跨团队扩散（从尝鲜到组织覆盖）
- 留存率升 → ④ 可积累（配方、偏好、语义层）
- 导出/复用 → ② 可消费（交付物有价值，不止聊天记录）

判断：追问率与留存率支持判断「愿深聊、会回来」；渗透率提供是否走出早期用户圈的信号。

## 收束：五句话

1. **问题**：Data Agent 易成花瓶——可信是第一位，但只有准还不够
2. **表象**：黑盒、难信、聊完就散、越用越不聪明
3. **原因**：QA 思维、缺过程协议、可信押模型、重水上轻水下
4. **应对**：Spec 驱动 + 流式协作 + 可信机制 + 多引擎编排 + 鸭子浮水
5. **效果**：追问、导出、留存——用户已用脚投票

**Takeaway**：把「怎么分析」写进可复用规格；单次靠可追溯证据链建立信任，跨轮靠偏好与配方持续积累。用户上次分析完，留下了什么？若答案是「没有」——产品还没开始建壁垒。
