## 业务背景与挑战

信飞科技处于国内互联网金融产业链的科技金融环节（与蚂蚁、度小满、京东数科同列）。行业全景：顶层为监管（中国人民银行、金融监管管理局、证监会）与行业协会（中国互金协会、中国银行协会等）；产业链为获客 → 风控 → 放款 → 贷后管理；行业底层支持包括数据服务商（同盾、百融等）、增信机构、技术服务商（阿里云、商汤等）、催收机构、征信机构（中国人民银行征信中心、百行征信、朴道征信、钱塘征信）。

**多国展业模式**：A 国、B 国、C 国、D 国……均以"科技金融"形态复制展业（"Copy" of A / "Copy" of A / "Copy" of C / "Copy" of D），每个国家平台建设、数仓建设独立部署。

面临的挑战（采建管用四环节）：

- **采**：ods 单任务人工配置耗时长；新国展业时采集任务多工作量大；多源（Mysql/Mongodb/Kafka）无法模版化，容易配置错
- **建**：大部分的 DWD 层建设和 ods 没有区别；关键业务流程依赖口传，新人无法独立完成；新国家展业时 DWS/ADS 有一定重叠，但每个国家都要有
- **管**：多国需求的并发导致 DQC 容易漏，质量问题被动响应；敏感字段识别、权限都靠人，容易错/漏；慢任务/无效任务治理滞后，出现问题再治理，没有预防
- **用**：多国业务指标口径不是 100% 一致，人工容易错；部分业务不熟悉 sql 语言，依赖数仓分析；数据异常排查耗时长，需要逐层追溯上下游

## 方案演进：三个阶段

### 方案 1——没有 AI 的时代（人工搞）

新国家（如 B 国）上线全部人工：ods 接入配置重新接入一次；基线配置可以参考 A 国但需要注意时区；dwd/ads 绝大部分情况可以 Copy A 国代码，但发布任务以及依赖的任务还是需要人工搬运；dqc 参考 A 国重新配置，通用规则可复用但仍要人工配置；各国业务参数不一样，找任务、改任务需要大量人工工作（内容不复杂）。

### 方案 2——基于 Dify 的效率提升

链路：Mysql Table schema →（提示词+模型+工作流，Dify 平台）→ ods 接入加速（data x 的 json）→ ods 到 dwd（提示词+模型+工作流，Dify 平台）→ dwd 层代码生成 → 修改提示词/Dify 工作流修改 → 验证结果准确性 → DataWorks 试跑 → 上线。另有基于自然语言的数据查询链路：自然语言 → 提示词 → 模型 → 工作流（Dify 平台 + Dataworks api + 钉钉知识库）→ 直接给出结果。核心动作仍是 Copy A 国代码。

### 方案 3——基于 Data Agent 的能力革命

- **采**：ods 层数据建设（skills）
- **建**：dwd、dws、ads 任务生成&修改（skills）
- **管**：慢任务分析、无效任务、存储治理等（语义层）
- **用**：报表生成、问数、问题溯源等（语义层）

两类任务开发：

- **通用型任务开发**（提示词+模型，Data Agent）：数据接入、任务发布/下线、血缘分析、简单的 dwd 任务、dqc 配置、慢任务分析、增全量合并……
- **包含业务语义的任务开发**（提示词+企业语义层+模型，Data Agent）：指标查询、问题分析、口径探查、简单的口径修改、报表生成、基于业务语言的需求开发……

### 如何构建准确的语义层

示例需求：一段话的需求（比如将 xx 指标的计算阈值从 A 改成 B）；一个数据问题（比如为什么这个用户在这个表里面会有两条数据）；系统重构评估（帮忙评估下表 A 的兼容方案和改动成本）；字段语义疑问（这个表里面的这个和 days 相关的字段有什么区别）。

方法论（基于知识库、skills、大模型三类组件）：

- 人工验证 → **找到 Agent 的盲点**（完善知识库）
- **找到 Agent 的断点**（通过 skill 串）
- **找到 Agent 的限制点**（调整参数/绕过）

## 问题和解决方案

| 问题&难点 | 解决方案 |
|-----------|---------|
| 知识库准确性建设和保鲜 | 目前定期人工更新，未来可能通过 git 的方式进行管理，结合任务的发布、更新下线，自动更新知识库 |
| 知识和 skill 无法多人互通 | 目前正在和阿里云探讨解决方案 |
| 任务过长容易超时 | 短期内只能控制输入任务的长度，比如对于 ods 采集的任务，试出来的上限差不多是 10 个一批可能就是极限了 |
| 向量数据库不准确 | 没有花太多时间去调整向量数据库的参数，对于同一份企业知识文档，在相同的问题下，Data Agent 效果会好很多 |
| Data Agent 费用问题 | Data Agent 用了通用资源组，对于非包年包月的场景会有额外的费用，建议包年包月 |
| Dataworks Api 调用频率限制 | 通过增加重试和优化无效 api 调用可以缓解，但是无法根除，最终切换到 Data Agent 解决 |
