# vivo 数据研发治理平台 DataAgent 实践

> 演讲者：王同欢，vivo 大数据专家，15 年手机互联网中间件与大数据平台研发经验，0→1 建设 vivo 数据研发治理平台 BDSP
> 论坛：2026 Agent 大会「面向Agent的数据架构论坛」
> 主线：**Chat → Copilot → Agent**；人从操作者走向审核者（2024 探索，2025 Copilot 落地，2026 推进 Agent 落地）

## 背景与平台：为什么 Agent 从数据平台里长出来

**BDSP（vivo 数据研发治理平台）**：践行 DataOps 理念，服务全公司数据开发、数据分析师、数据产品经理等角色，提供数据采集、管理、加工、使用全流程支持的一站式平台。三层结构：

- **用户能力层**：数据集成、数据管理、数据开发、即席分析、数据服务、资源治理、组件服务
- **组件服务层**：计算引擎（离线计算/实时计算/OLAP）、数据基础设施（数据采集、存储服务、消息中间件）、平台运维
- **运维支持体系**：统一监控、稳定性保障、成本与资源管理、平台运营

平台价值：让研发治理能力面向用户场景聚合，并由统一组件与运维底座持续支撑。

### 数据智能体演进：从能力探索到自主执行

| 时间 | 里程碑 | 效果 |
|------|--------|------|
| 2024 | Copilot SQL 助手（任务 SQL 解释、失败日志自动诊断、生成 SQL 摘要、解释任务逻辑）；离线任务智能诊断 | 识别率 96%+ |
| 2025 | 数仓问数能力（SQL 生成/纠错/优化） | 采纳率 60%+ |
| 2026 | 覆盖四大数据领域，从辅助走向自主执行 | 数仓自助问数，自动生成 SQL、自动执行 |

## AI 能力破局：模型会写 SQL，不等于用户敢用

### SQL 助手：直接选择 NL2SQL

三种路线对比：

| 路线 | 做法 | 边界/判断 |
|------|------|----------|
| 规则模板 | 意图识别、槽位填充、固定 SQL | 可控但覆盖有限，模板维护成本高 |
| 语义层先行（NL2SemQL） | NL→SemQL 语义层编译→SQL | 前提是先建统一语义层；当时 vivo 尚不具备 |
| **直接 NL2SQL（我们的选择）** | LLM 直接生成结构化 SQL | ① 无前置语义层 ② SQL 结构化、相关训练语料丰富 ③ 2024 接入后对 LLM 演进有信心 |

选择依据：不等待语义层，也不增加 SemQL 中转——问题直接约束成可生成、可校验的 SQL 任务。2025 年重点：跑通问题理解→SQL 生成→执行校验→反馈优化的完整闭环。

### 数仓问数：固定工作流（六个固定节点）

让每一步可评测、可回放：需求澄清（信息不足时多轮澄清）→ 信息召回（表结构与相关知识按需召回）→ 问题改写（结合上下文改写成独立完整问题）→ SQL 生成（基于召回上下文生成 SQL）→ SQL 执行（真实执行，拿到结果或报错）→ 纠错（执行失败自动修复重试，修复后重新执行）。通过代码固化，节点输入输出全留痕，失败可回放可归因——常见问数被拆成固定管线，节点确定、边确定、每步可观测，准确率稳定可控。

### 三层协同优化（准确率 90%+）

把复杂性前置到数据和系统，让模型专注理解意图、生成正确 SQL：

1. **第一层·数仓结构治理**：字段语义消歧（统一命名与口径，降低误选字段）、主题宽表构建（前置整合多表关系，减少跨表推理）、查询空间收敛（聚焦必要表字段，减少检索干扰）
2. **第二层·提示策略优化**：任务分步约束（固化选表、过滤、聚合、校验路径）、时间槽位标准化（先换算时间，再生成分区条件）、SQL 规则注入（明确方言、边界与异常处理）
3. **第三层·业务知识补全**：指标口径补全（补充指标定义、算法与适用范围）、枚举语义映射（提供状态值与自然语言映射）、多路知识召回（按需召回历史 SQL、规则与元数据）

### 固定工作流的边界

- 已经跑通：编译期确定的路——口径明确的单轮问数、常见指标查询与取数，流程稳定、可评测、可回放
- 仍然卡住：执行结果决定的路——多步分析（下一步依赖上一步的执行结果）、流程固化（流程在代码中固化，无法按结果调整）、人工拆解（复杂分析仍需人先拆成单步问题）

新的问题不再是 SQL 能否生成，而是**复杂任务的下一步无法预先确定**——让模型在每轮结束后重新决定下一步，这正是引入 ReAct 的动机。

## 产品与架构：两种产品形态，共用一套生产级 Agent 底座

- **产品层**：BDSP Copilot（平台内置、专业用户）+ AnyData（独立入口、业务用户）
- **Agent 层**（产品专属）：数据开发智能体、数据运维智能体（建设中）、问数 Agent、分析 Agent、洞察研究 Agent
- **编排层**（产品专属）：任务上下文、变更 DIFF、确认执行、审计、指标澄清、分析计划、证据引用、报告交付
- **共享 Agent 工程底座（BaseAgent）**：语义与指标、SQL 能力、Tool/Skill、Agent Runtime、Memory、Guardrail、评估与观测
- **共享数据基础**：BDSP 数据研发治理平台、数据资产、大数据基础资源

上层按用户任务优化，底层把能力与知识沉淀复用起来。

### V1 → V2 → V3：从流程驱动走向目标驱动

| 版本 | 形态 | 关键设计 |
|------|------|---------|
| V1 | 固定工作流 | StateGraph 6 节点 |
| V2 | ReAct 改造 | Thought/Action/Observation 每轮三要素，由模型决定下一步 |
| V3 | BaseAgent 自主规划 | OpenCode 风格 while(true) 循环，沉淀为可复用的基座；子类继承基座，只实现专业逻辑 |

V1 证明问数可行，V2 让流程会思考，V3 把思考能力沉淀成所有 Agent 共享的基座。

### BaseAgent：生产可用的统一 Agent 底座

五大能力：模型接入、Agent Loop、工具系统、上下文工程、分层记忆。三道机制保障生产可用：

- **Agent Loop（生产级循环）**：6 步循环（预算→插话→推理→工具→恢复→保存）；可打断（插话合并进当前轮继续推理）；可恢复（从最近恢复点继续执行）；互斥锁（同会话同时只允许一个 Loop）
- **工具系统（按需检索+安全拦截）**：60+ 工具一句话命中，不塞满上下文；场景过滤（确定后解锁对应工具组，动态收紧）；权限拦截（校验资格 + SQL 逐张鉴权）；安全执行（自动脱敏 + K8s 沙箱隔离）
- **上下文工程（压缩+隔离）**：压缩（子代理 + 轻量模型，保留决策信息）；恢复摘要（压缩后仍可从摘要继续执行）；子代理隔离（脏活累活不进主上下文）；只回传结论（主 Agent 只看结论与证据）

稳定的循环 + 克制的工具 + 不膨胀的上下文 = 生产可用的智能体底座。

### 分层记忆与反思进化

三层记忆：① 短期记忆（对话后生成摘要，跨会话连续）、② 长期记忆（沉淀偏好、规则和可复用经验）、③ 反思与遗忘（去重、合并、更新，删除过期）。

反思进化四步：① 02:00 触发（定时 + 阈值 ≥5 条 + 手动，三通道）→ ② 短期聚类（扫描 7 天窗口，按主题聚类）→ ③ LLM 反思（工具提交，Schema 自动生成）→ ④ 三类产出落库（短期整合更新、长期审计留痕、深层洞察）。

读写原则：先目录后详情（L0 目录 → L1 概览 → L2 全文），异步隔离可更新。成本与安全：24h 冷却（同一用户一天只反思一次）、7 天窗口（只看最近一周，不背全量历史）、防并发（跳过在跑任务，用户间 100ms 限速）、提交（模型用工具提交结构化结果，可校验可回归）、安全边界（新记忆打分过滤后入库，过期/错误记忆自动淘汰，高危变更需人工确认）。记忆的价值不是"记得多"，而是**找得准、读得轻、更新可控**。

### 评测：Agent 持续优化的导航仪

- **找问题**：早期"够用就好"（SQL 助手、数仓问数时代）——输入 + 结果 LLM 评估，三段检查（语法/语义/逻辑），错误自动沉淀为评测样本，低成本建立反馈闭环
- **找方向**：后期"体系化"（AnyData、深度研究智能体时代）——过程评测：每个 Span 都可评，多步失败可归因到具体环节；全链路可观测：输入输出可回放；错误资产化：纠错工具 + 样本库
- **评效果**：回归评测防退化——用回归结果判断优化是否有效，错误不再丢，变为优化资产

不用等能力齐备，"输入结果 + 大模型评估"就能开始，关键是让评测能长期指导优化。

## 落地实践：两类 Agent 进入真实业务链路

### 数据开发智能体：Agent 执行，人拍板

当前覆盖开发六步：找数找表 → 任务开发 → 结果表创建 → 依赖调度 → 自动测试 → 发布上线。安全边界（Agent 不绕过平台）：建表必确认（DDL 变更前展示差异，用户确认后才执行）、上线必确认（发布前展示变更内容，Agent 执行人拍板）、全程可审计（上下文、变更 DIFF、确认记录全程留存）。

未来：从需求源头自动流转——当前是业务方→数据产品→开发→AI 接管（仅开发环节）；目标是 AI 分析拆解（理解业务需求→数据任务）、自动转化（需求语义→开发测试动作）、流转推进（需求→开发→测试→上线）。开发环节提效是量变；从需求源头自动拆解、转化、流转，才是全流程的质变。

### AnyData + StarRocks：分析智能体全局架构

Agent 负责规划，StarRocks 负责执行与稳定交付：

- **Agent 编排层**：自然语言问题 → 规划（任务拆解）→ 执行（工具调用）→ 校验（结论核验，样本/全量）→ 报告（图表，可追溯可导出）——目标转成可执行、可校验的任务
- **统一数据平面（StarRocks）**：统一访问（Hive/SR）、身份直达（权限透传）、结果分级、慢查兜底（Spark 双轨）
- **数据资产与计算后端**：Hive 数仓、SR 原生表、HDFS/ORC、Spark 兜底

规划与执行分离，分析才能既自主又稳定。

### AnyData 三种运行模式

1. **Data Query**：直接取数——单轮问答，问数即答
2. **Analysis**：多步分析——自主规划，逐步执行（执行链：① 自主规划：LLM 把复杂问题拆成有序计划 → ② 委派子代理：子代理逐步执行，中间结果隔离 → ③ 生成分析报告：报告技能生成 HTML 报告页 → ④ 导出交付：自动截图排版，导出 PDF/PPT）
3. **Auto**：自动分流——系统判断走取数还是分析

最终产物是结论、数据、图表和文件，不是一段自然语言。规划、委派、生成、导出各就其位——AnyData 交付的是一份可导出的分析报告。

### 推广：选对种子团队（四项筛选标准）

① 团队意愿（愿意投入时间反馈口径、验证结果，和平台团队一起调优）② AI 认知（知道 Agent 需要迭代优化，不当作一次上线就完美的软件）③ 准确率认知（理解准确率边界，愿意通过校验、确认与样本集把效果调稳）④ 场景容忍（业务价值明确，允许在护栏下逐步提升准确度）。推广路径：候选团队→四维筛选→锁定场景→共创调优→样板验收。种子团队不是第一批用户，而是共同打磨样板的产品合伙人。

## 知识资产化：从录入到编译，让知识随业务生长

Agent 能力就绪之后，知识体系才是效果的保障。两类知识：

- **平台已管理（结构化元信息，自动化梳理）**：任务 SQL（调度任务定义的查询逻辑）、库表元数据（表结构、字段类型与注释）、数据质量规则（校验逻辑与告警阈值）、历史执行 SQL（用户真实查询日志与样例）、上下游血缘（表级与字段级数据流向）、调度依赖关系（任务产出时序与阻塞链路）
- **平台外（业务语义信息，用户主动维护）**：指标口径（计算逻辑与统计范围定义）、维度定义（分析视角与枚举值约束）、行业术语（业务领域专有词汇与缩写）、专业名词（技术概念与同义词映射）、业务规则与场景（使用条件、约束与边界说明）、常见问题与归因（异常解读与排查经验沉淀）

**现状的痛**：业务知识靠人工录入和 Excel 批量导入——更新滞后（代码改了，知识库还是旧的）、覆盖有限（只有被录入的知识才能被用上）、成本线性增长（业务每扩展一步，维护多加一分）。

**目标**：让 Agent 直接连接持续变化的 Git 仓库与公司 Wiki，知识随代码和文档一起更新，不再需要第二份手工拷贝。知识接入方式决定 Agent 能力上限——手工维护的知识，追不上持续变化的系统。

### LLM Wiki：从碎片检索到完整页面，知识生产自动化

为什么需要 LLM Wiki：Chunk RAG 把文档切成 Chunk 进向量库，召回重写/重排，上下文断裂，拼不出完整主题；LLM Wiki 按主题组织成整页，一个主题一页、层级清晰、上下文完整，页面绑定来源可持续增量同步。

知识生产管线四步：① 来源（三类知识源头汇聚：平台资产表/任务/指标、Git 仓库代码与文档、公司 Wiki 业务规则与流程）→ ② 解析（多格式解析 Markdown/JSON/YAML/HTML，Tika 兜底复杂格式）→ ③ 生成（按主题组织成完整页面，页面绑定来源可增量刷新，页面即模型可读的知识单元）→ ④ 消费（Agent 按主题加载整页，与预召回、语义模型打通，知识更新随代码发布生效）。

> RAG 回答"哪里提到过"，LLM Wiki 回答"完整是什么"；知识能自动生成，Agent 才具备复制基础。

## 未来思考：Agent 互联与 Harness 趋同

### Agent 互联：让专业能力成为企业可组合的服务

桌面智能体统一承接意图（员工/业务用户提出一个目标：查数据、建任务、治问题），通过互联协议编排专业 Agent 能力池协同完成端到端任务：① 问数/分析 Agent、② 数据开发 Agent（建表/调度）、③ 数据治理 Agent（质量/资产）、④ 数据运维 Agent（监控/处置）、⑤ 知识服务 Agent（语义/知识）、⑥ 流程协同 Agent（审批/协作）。专业 Agent 各司其职，串联才是核心价值。

### 未来判断：Harness 趋同，串联才是核心价值

Harness 能力将逐步趋同：推理与规划（Loop/ReAct/规划，通用 Agent 标配）、工具与执行（注册/沙箱/权限拦截，平台统一收口）、模型与上下文（多模型路由/记忆压缩，业务无感）。

业务平台聚焦差异化：Skill 技能（Markdown 技能文件，按意图挂载、热更新）、业务 Tool（60+ 专业工具沉淀在平台，能力工具化）、语义资产（字段枚举/口径/业务知识，模型可读上下文）。Harness 趋同让 Agent 通用化，平台差异化在于 Skill 与业务 Tool。
